# #87 批量绘图与持久队列

## 实现

一次提交 1–99 个独立单图请求，数量与并发默认均为 1；数量、并发（1–4）和完成提示音开关随草稿持久化。没有额外等待项数量上限。运行中可以编辑下一份草稿并追加批次，页面切换不拥有任务生命周期。

`DrawingRepository.enqueue` 在一个 Dexie 事务内分配递增 `queueOrder` 并 `bulkAdd` 整批任务，冲突整批回滚。每项都有独立 ID、批次 ID、请求快照及有序参考图描述符，不在排队时复制图片字节。登记期间同步防重，按钮忽略原生双击的第二个 click，后续独立点击仍可追加同一草稿。

`DrawingController` 按持久 FIFO 取得槽位，覆盖准备、读图、网络、文件保存及 DB 提交。提高并发立即补槽，降低不取消在途项。单项服务或保存失败继续后续队列，不自动重试。耗时从准备开始至保存结束，排队不计入；崩溃时没有可靠结束时间则显示未知耗时。

派发解析原供应商、连接和模型 ID，地址、协议或实际模型改变则阻止该项。Key 在执行时读取并冻结在闭包，不进入持久快照。排队／运行／登记期间保护共享配置及维护操作，但不关闭聊天发送。

## 恢复边界与 #88

本次纳入必要底线：单项／全部待处理项取消、暂停／继续、退出保留队列和重启暂停。queued/preparing 确定未发送；运行前耐久写入 running，崩溃后保守归为结果未知，绝不自动重发。取消已发送项只停止本地等待，不能撤销远端生成或计费。saving 不接受取消。

启动先沿用 pending/manifest 恢复，再将 preparing 恢复为 queued 并暂停。手动继续只派发确定未发送项。保存重试只读取日志／写入已有响应，不调用服务。文件已耐久保存后，即使 DB 登记失败也释放整份响应，可从本地日志恢复。暂存失败时响应保留在当前进程，退出可能丢失，关闭需要单独确认。

#88 **未完整完成**：批次专用管理、重新生成与来源链、终态历史删除／批量清理、特殊删除确认、完整失败诊断及失败资源管理仍留待 #88。连续磁盘失败时内存响应可能累积，需由 #88/#94 继续处理和压力验收；不暗改自动暂停，不宣称此路径已有内存上限。

完成事件在有未结束任务变为全部终态时触发一次；全部成功与含失败／取消／未知项采用不同音高。历史重载不响铃；恢复同批剩余任务时计入该批未知／失败项。Web Audio 在用户交互时启用并释放音频资源；原生听感待人工验收。
