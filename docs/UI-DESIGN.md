# Ayase Studio UI 设计规范

整理日期：2026-10-02。本文是 UI 开发入口：先读当前规范，再按模块查实现与历史依据。用户当前明确指示优先；下面“当前规范”取代历史中冲突的布局或视觉描述，未覆盖的功能细节仍查对应专题。功能、数据与协议约定分别见 [PLAN.md](PLAN.md)、[ARCHITECTURE.md](ARCHITECTURE.md)、[DATA-CONTRACTS.md](DATA-CONTRACTS.md) 和 [PROTOCOLS.md](PROTOCOLS.md)。

## 当前规范

常规页增加“绘图输出”分组：可复制并换行显示完整当前路径，提供“选择文件夹／打开文件夹／恢复默认”，说明设置仅用于本机、更改仅影响新任务。读取／选择／验证期间按钮禁用；取消保留原目录，失败常显具体提示，未知配置只能重新加载而不能覆盖。绘图成果操作栏增加“更改输出目录”进入常规设置。原生目录选择与权限检查由本机完成，浏览器使用模拟边界验收。

绘图操作成功提示（如“已删除 N 项成果”）放在工作区右下角不拦截点击的小浮层，不占用顶部布局；错误、加载及未保存图片风险提示保持原位置。

2026-10-03 临时绘图操作：右侧“生成历史”标题右端增加带垃圾桶图标的红色“清空历史”按钮；空历史和管理操作不可用时禁用。复用现有成果批量删除与确认流程，确认范围包含全部分页、固定为打开确认框时的成果，保留任务记录、草稿和预设及仍被引用的图片。确认期间新增成果保留，目标成果变化时要求重新确认。定向界面测试与隔离浏览器清空验收通过；未操作真实历史。

### 开关与复选框（2026-10-03）

共享实现为 [ToggleControls.css](../src/ui/ToggleControls.css)，由 App.css 引入，仅通过显式控件类应用；不影响消息 Markdown 中的任务列表。开关 36×20px，复选框与管理态选择标记 18×18px；强制颜色模式下原生输入恢复系统绘制。验证范围见 [开发记录](DEVELOPMENT.md#switch-and-checkbox-unification-2026-10-03)。

持续性的布尔设置统一使用紧凑滑轨开关：常规页的后台运行／退出前确认、流式输出、显示思考内容、绘图完成提示音、搜索服务启用、侧栏／输入区域玻璃及备份加密。开启使用主题强调色，关闭使用中性底色，同时以滑块位置区分状态；沿用现有语义配色、清晰焦点、禁用反馈及减少动态效果设置，不新增玻璃或卡片。常规和外观设置保持文字在左、开关在右，紧凑工具区保持就近排列。

外观变更不改变保存时机：即时偏好沿用即时保存，搜索等表单仍需保存后生效，备份加密仅控制本次导出选项。开关必须有可访问名称和开关语义，支持键盘操作，不通过颜色单独表达状态。

选择对象和操作确认保留复选框：导入助手／对话（含部分选中）、恢复策略／覆盖密钥确认、退出弹窗“不再提醒”。头像库和背景库在管理模式保留多选语义，统一空选与选中标记；普通选择模式不显示管理复选框。统一复选框的尺寸、圆角、主题色与焦点，保留高对比模式可辨识性。此规则取代旧专题中对上述设置使用复选框或“已开启／已关闭”文字按钮的外观描述，不修改其业务约定，也不新增其他列表的批量操作。

托盘菜单紧凑调整：取消底部常驻错误提示占位，菜单从 150px 缩短至 131px，含阴影边距的原生窗口同步从 166px 缩短至 147px。三行操作仍为 36px，上下内边距一致；错误仅在发生时显示为首行副文本，保留可访问提示且不扩大窗口。

2026-10-03 托盘右键菜单改用独立小窗口：12px 圆角、不透明浅深主题底色、细边框、轻阴影及图标，保留“打开 Ayase Studio／设置／退出”，退出前加分隔线。方向键、Home／End、Tab 与 Escape 可操作，失焦收起，按所在显示器工作区限制位置。后台运行开关、默认值和退出风险保护不变；自定义菜单未就绪时保留原生菜单回退。浏览器样式与自动测试通过，实际 Windows 托盘交互和混合 DPI 仍待体验，详见 [开发验证记录](DEVELOPMENT.md#rounded-tray-menu-verification-2026-10-03)。

设置分类简介以用途概括为主，不枚举具体服务商、字段或当前子功能；页头用一句话说明页面用途。保存、测试、费用及数据风险等操作细节放在对应控件或帮助说明中，避免让总简介承担操作手册的职责。

2026-10-03 #114：设置分类依次为常规、连接配置、外观、网络搜索、数据管理、关于，首次进入设置默认常规。原头像页并入常规的“个人资料”，日常头像预览 64×64px，取消独立聊天效果大预览；更换头像／管理头像库复用原头像库弹窗，裁切保留大编辑区域。“窗口与退出”包含默认开启的后台运行与退出前确认。托盘左键恢复，菜单提供打开、设置和明确退出；设置恢复已有窗口并进入常规，保留草稿与任务，不绕过启动或备份保护。隐藏不弹普通退出确认，也不停止任务。普通确认中的“不再提醒”可从常规开关恢复，不影响绘图风险确认。后续应用级行为及个人偏好按实际用途加入分组，不预留空功能。功能实现与浏览器／原生／用户交互验收分别记录。

2026-10-03 用户确认最左功能栏收窄，后续反馈由 52px 继续试调为 48px，两侧留白各 6px，仅显示 19px 图标；36px 按钮保留可访问名称、悬停名称与键盘焦点，Logo 为 28px。最左栏和 40px 顶栏融合为一层连续外框，内侧转角 12px、图标按钮 10px 圆角，底色只合成一次。新增“顶栏与功能栏背景透明度”，两处共用数值；人物壁纸六轮对比后，外框默认 40%，助手／对话侧栏默认 50%，消息气泡默认 12%，侧栏玻璃仍默认关闭。对话正文与输入是首要注意区域，导航退后；建议外框 35%–45%、侧栏 45%–55%、气泡 6%–12%，作为当前样本下的调节起点，设置仍允许完整 0–100% 范围。只改变背景，文字与窗口控件保持清晰。外框在聊天、绘图、设置一致，外观聊天预览同步；助手／对话列表及设置分类导航由侧栏透明度控制，统一滑块覆盖四个区域。此项取代下方“顶栏始终透明”的显示规则；100% 可恢复全透明背景。已有显式设置保留，对应区域恢复默认使用新数值。参考仅为用户截图的层级与比例，自有实现，不复制第三方源码或素材。生成的人物背景及纯色下的浅深主题对比已完成，实际壁纸观感及原生拖动／窗口按钮仍需用户体验。

未开启侧栏玻璃时，聊天导航以浮层展开会增强底色，不透明度至少 94%，减少下方正文的干扰；不写回保存值。桌面并排导航继续使用保存的透明度，玻璃开启沿用现有模糊材质。此规则按实际浮层状态判断，外观帮助说明同步解释。详见 [本轮人物壁纸对照](APPEARANCE-TRANSPARENCY-COMPARISON.md)。

后续窗口与弹层统一整改入口见 [窗口、弹窗与浮层清单](UI-SURFACE-INVENTORY.md)：包含独立工作区、配置／资源弹窗、确认框、小浮层及系统文件窗口边界。清单仅为盘点，不代表已经整改或验收。

### 排布与信息层级

- 页面外侧留白与内部卡片间距分别设定，不能把紧凑分栏的 4px 直接套到设置页面边距。用户体验后要求横向空间再次翻倍，连接配置和外观页当前左右 40px、上下 16px，窗口不超过 760px 时左右 24px；普通页头无额外 padding，标题区与内容间隔 16px。此规则取代下方首版试调中的 4px 页面外侧留白及中间版 20px／12px，内部排布不变。
- 先明确主要任务、常用操作和次要信息，再决定容器。相关内容通过对齐、间距和共享底板形成整体，避免每块文字或每行数据各套一张卡片。
- 操作靠近作用对象。高频入口直接可见；低频操作可以收进“更多”，说明跟随对应操作。错误、未知结果和可能丢失数据的提示不能为整洁而隐藏。
- 统一同一区域的外边缘、文字基线和控件高度。高度应包含行高、内边距与边框；折叠箭头用现有 SVG 图标，避免字符基线造成错位。
- 明确比较哪条对齐线：聊天以气泡与输入框的外边缘为基准；表格以列为基准；标签和复选框以内容居中为基准。不要靠补空格或孤立偏移修正结构问题。
- 响应式优先依据容器可用空间，允许换行或重排。长名称可截断并提供完整值入口；长正文可换行，代码和大表格局部滚动，不撑宽页面。
- 以用户提供的 2K 布局体验为绘图基准，同时照顾窄窗口。物理分辨率不直接等于 CSS 可用宽度，需考虑窗口与系统缩放。

### 表面、边缘与文字

2026-10-03 常规页头像弹窗：更换头像／管理头像库移除嵌套旧页面卡片边框，统一 24px 外侧留白（窄屏 16px）、64px 当前头像、12px 网格间距与分隔的底部操作区。管理入口直接进入已有多选管理状态；更换入口保持选择应用。仅作用于常规页用户头像弹窗，背景库和助手头像选择器不变。

2026-10-03 外框衔接修正：聊天、绘图和设置顶栏统一移除底边框，避免直线横跨外框内侧圆角；顶栏高度和连续外框材质保持不变。

2026-10-03 后续间距调整：绘图工作区外侧留白从 8px 收至 4px，缩小顶栏下方缝隙并统一模块外侧间距；面板之间仍为 8px，卡片内部留白不变。此项取代下段的绘图外侧 8px。

2026-10-03 设置／绘图容器：用户要求用上一轮生成的人物背景对比，并明确两页应按各自任务设计、共用视觉语言。对比原样、不透明底板、7%／15% 轻透后，用户确认采用不透明的主题派生底色（面板色 98% + 正文色 2%）、正文色 8% 的轻描边、12px 圆角及 1px／2px、3.5% 的弱阴影。外观分组、连接树／详情、网络搜索、数据管理、头像卡片、关于与绘图面板复用 `--workbench-*`；不继承聊天透明度，也不增加玻璃或偏好。设置内容滚动区移除重复外框；原页面留白保留。连接分栏及绘图面板间距从 4px 调整到 8px，绘图外侧 8px，参考图区改为浅底分组，图片画布保持原有不透明底色、图片不加滤镜。强制颜色模式保留系统色边界。此为用户确认的本轮样式，浏览器调试不代表原生交互验收；各主题、背景与窗口检查见 [容器对照记录](WORKBENCH-MATERIAL-COMPARISON.md)。

2026-10-03 后续实施约定：在用户认可输入框材质后，增加两个独立持久开关。聊天助手栏和对话栏共用一块更克制的玻璃底板：浅／深底色 alpha 为 0.52／0.62，8px 模糊、1.1 饱和度，弱渐变与顶部高光；停靠时无外投影，覆盖正文时保留浅阴影。用户随后要求加强玻璃轮廓、保持模糊强度：浅／深白色描边 alpha 为 0.48／0.22，顶部 1px 内高光 alpha 为 0.70／0.30；预览同步轮廓。输入框沿用已认可参数。按用户后续确认，侧栏默认关闭、输入框默认开启；新配置、旧配置缺失字段及恢复默认均使用此组合，已有显式选择保持。开启时材质覆盖对应透明度显示；滑块保留并说明是保存值、关闭玻璃后使用，不自动重置值。统一透明度按当前外框规则编辑四个保存区域。预览同步；消息气泡、设置分类导航和菜单不增加玻璃。以下临时样板的“直接启用／暂无开关”描述仅为历史，现由本条取代。完整实际界面及性能验收见 [收尾记录](ISSUE-98-108-CLOSEOUT.md)。

2026-10-03：用户反馈首版只有模糊、缺少玻璃质感后，输入框样板改为 8px 模糊、1.15 饱和度、主题底色、125° 微渐变、顶部 1px 内高光与浅阴影。浅／深色底色 alpha 分别为 0.32／0.46，渐变叠加后的最终透明度不同；浅深主题分别调校亮边与高光，焦点保留独立强调圈。只借鉴 MONA 输入框的材质组成思路，未移植其源码或素材。样板临时覆盖输入栏透明度的显示效果，不改写保存值；用户认可后再实现覆盖透明度设置的正式开关。外观预览共用 `.composer-frame`，布局不变，不扩展到侧栏、气泡和菜单。不支持滤镜时保留原底色与透明度；强制颜色或减少透明效果偏好下使用不透明底板、移除滤镜和装饰阴影并保留焦点。此为待体验样板，不代表 #98 完成或性能已验收。

- 复用现有 `--color-*` 语义色与 `--font-*` 字号，保持系统字体栈。不要把第三方色值整套写死，也不要默认中文标题需要负字距。
- 用字重、字号与位置表达层级。正文优先可读，次要标签适度弱化；危险操作、错误和键盘焦点保持辨识度。
- 耗时、Token、计数、页码等数据使用 `font-variant-numeric: tabular-nums`；位数变化仍可能改变宽度，需要稳定位置时另留空间。提示词正文不强加数据排版规则。
- 边框只负责必要的分界，不让每个次要按钮都有同样强的外框。半透明描边不保证适配任意背景，必须结合主题及实际底板判断。
- 弱化装饰仍须保留分组归属和可点击性。宽列表中的名称与操作距离较远时，不同时撤掉分组边界和按钮底色；可用淡边框、轻标题底色和常驻按钮浅底建立联系，而非只追求边框少。
- 圆角按部件角色协调。等距、紧密嵌套的轮廓可参考“外圆角 = 内圆角 + 间距”；普通面板内的每个按钮不必满足同心公式。
- 深色浮层可略亮于底板，使用主题色派生；不要仅因 `z-index` 更大就机械提亮。当前聊天与绘图浮层使用面板色轻混合文字色，保持不透明。
- 聊天保留用户设置的背景、遮罩和透明度；底板透明不带着文字图标一起变淡。气泡只合成一次底色，避免嵌套重复透明层。任意背景配极端透明度不承诺对比度。
- 阴影用于说明覆盖关系，例如菜单或覆盖正文的导航；停靠导航不额外悬浮。内高光、多层阴影、毛玻璃不是所有部件的默认装饰。

### 开发与验证方式

1. 改动前确认部件职责、当前有效规则及 CSS 覆盖关系。复用既有语义变量；相似视觉不意味着需要立即抽象新组件或引入动效库。
2. 小幅 CSS 调整检查作用范围、禁用／选中／拖动、减少动态效果及 diff，由用户快速体验；不为每个像素变化重复全量构建或大范围截图。
3. 改变交互行为时补相应确定性测试；跨模块、数据、安全等改动仍遵守仓库独立审查和验证要求。文档整理只需内容、链接及差异检查，详见 [DEVELOPMENT.md](DEVELOPMENT.md)。
4. 跨页面推广时针对新增范围核对浅／深主题、窄窗口、长内容及键盘焦点。浏览器使用隔离数据，不调用真实模型；实际 WebView2 与原生交互另记用户验收，不把编译成功当成视觉通过。
5. 低成本优先：静态颜色、边框和数字排版；按需的短过渡。大面积模糊、动画阴影或大量同时变化的元素需单独评估，不能凭“纯 CSS”宣称无性能成本。无证据不报帧率或 GPU 开销结论。
6. 新反馈先更新上方当前规则及确认状态，再把被替代决定留作记录；不继续只往历史顶部追加新规则。局部参数调整注明范围，不自动升级为全局规范。

## 全局滚动条（#104，2026-10-02）

应用内所有普通滚动容器统一采用透明轨道、无两端箭头的圆角滑块。Chromium／Windows WebView2 的滚动条区域固定 12 CSS px，显示时滑块可见宽度约 6px，滑块悬停和拖动时约 8px（缩放时边框会按实际像素取整）；仅滑块变化，不改变占位宽度。按用户聊天页体验修正闲置规则：正在滚动或鼠标靠近实际滚动条边缘时显示，邻近区包括轨道及相邻 6px 内容，移回正文不再保持常驻。最后一次滚动结束约 700ms 后且鼠标不在邻近区时变透明；无需移到输入框，也不受背景图片影响。只隐藏视觉，不移除占位，不改变 overflow 或滚动行为；拖住滑块时保留按下态。横向与纵向采用同一规则，RTL 纵向条使用左侧边缘，颜色复用 `--color-subtle`、`--color-muted`、`--color-text-soft`，随浅色、深色、阅读及自定义配色变化。

出现采用 150ms 淡入，消失采用 200ms 淡出（ease-out），滚动后仍先等待 700ms 闲置。快速反复移入移出从当前透明度继续过渡；尺寸、轨道与占位不参与动效。系统开启“减少动态效果”时立即切换可见状态。浏览器数值属性动画在大树上仍可能刷新后代样式，因此每次显隐最多检查 500 个后代：达到阈值的区域直接显隐，保留所有滚动行为和隐藏规则，以长内容响应优先。

样式集中于 [src/scrollbars.css](../src/scrollbars.css)，由 `App.css` 全局导入；`main.tsx` 只安装一次 [全局滚动活动监听](../src/ui/scrollbarAutoHide.ts)。捕获 scroll 事件覆盖键盘、鼠标及程序滚动，每个区域独立计时；全局 pointerover／pointerout／pointermove 沿事件目标的祖先识别滚动条邻近区，正文容器的 `:hover` 不参与显隐，滑块悬停颜色也服从闲置隐藏。无需逐容器监听或完整 DOM 扫描。只有活动区域执行浏览器短动画，通过不向内容继承的数值属性控制滑块透明度，不覆盖组件原有 transition，不用 JavaScript 逐帧更新或 React 状态。闲置淡出完成后释放瞬时记录，热更新清理动画、监听、计时器及属性。新内容只需使用普通 `overflow: auto / scroll`，不需要单独挂类、包组件或重复配置；portal 弹窗同样生效。监听未安装时保留可见样式。聊天导航原有局部 `scrollbar-width: thin` 已移除。各页面的 `scrollbar-gutter: stable` 属于布局占位规则，按原布局保留，不统一强加到所有元素。

不支持 WebKit 滚动条伪元素的浏览器使用标准 `scrollbar-width`／`scrollbar-color` 回退，圆角、精确宽度及滑块悬停效果以浏览器支持为准。Windows 强制颜色／高对比模式不应用定制，沿用浏览器滚动条。系统文件窗口、原生下拉选项弹层等系统界面不由应用 CSS 控制。后续组件不得重复覆盖滚动条视觉规则，明确的特殊需求应先更新本节及全局文件。
