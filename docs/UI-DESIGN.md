# Ayase Studio 界面设计指示

## 历史输入浏览（#64）

输入框占位提示在发送与换行快捷键后补充“首行 ↑ / 末行 ↓ 浏览历史”；悬停提示进一步说明 ↓ 可返回较新输入或草稿。

2026-09-29 用户确认：输入框无选区、无修饰键且不在输入法组合输入时，第一显示行按 ↑ 浏览更早的当前对话用户文本，最后显示行按 ↓ 浏览更新文本，超过最新位置恢复进入浏览前的原草稿及光标。显示行包括自动折行；中间行保留正常光标移动。调出历史时 ↑ 将光标放到开头、↓ 放到末尾；因此多行候选中反向按 ↓ 会先向下移动光标，到底部才切换，可用 Ctrl+End 快速到末尾。长按重复事件不切换历史，Shift/Ctrl/Alt/Meta 和 IME 候选操作不抢占。

软折行交界处同一字符偏移可能对应前一行末尾或后一行开头。根据 End/右移、Home/左移和输入动作区分；鼠标定位等无法确定时保守保留原生光标移动，可能需要再按一次方向键，不提前覆盖输入。

历史仅包含当前对话可见、已提交用户消息的非空文本，不包含助手回答、其他对话、纯附件消息或隐藏问答版本；助手回复失败不排除已提交的用户输入。浏览只复制文字，待发送附件保持原样，不自动调出历史附件。原草稿和每个候选的临时修改分别保留，切换对话、助手或设置页后恢复各自状态。历史源被删除、清空或换版本后，未修改的旧候选不再提供；已修改的副本仍作为未发送草稿保留在可见历史之后，允许继续 ↑/↓ 找回，不复活数据库记录。

发送候选是发送一条新消息，提交成功后恢复原草稿；若异步准备期间用户已继续编辑或浏览，则保留最新输入。预检或保存失败不消费草稿。发送后结束该次历史浏览；未发送内容仅本次应用运行内保留，不承诺关闭重启后恢复。上述约定替代远端 Issue 中“恢复空白输入”的旧验收描述，远端未修改。

## 发送后滚动（#75）

新用户消息成功加入列表后直接滚到底部并恢复流式跟随，不播放平滑滚动动画。发送后用户再次主动上滚，沿用现有暂停与回到底部 48px 内恢复规则；编辑、重新生成、版本切换以及未加入消息的发送失败不强制恢复跟随。

## 聊天空状态（#73）

后续微调：提示改为“发送消息以开始对话。”，文字颜色固定使用主题正文色的 65% 不透明度（35% 透明），浅深主题共用，不随外观透明度滑块改变；头像样式不变。

2026-09-29 用户明确要求：无消息时仅显示当前助手头像及“发送消息以开始对话。”，不增加其他标题、说明或操作入口。头像复用现有组件，支持自定义图片、内置默认和旧 Emoji，切换助手同步更新，图片损坏沿用默认回退。空状态容器固定完全透明，不显示底板、边框或阴影，不受背景图片及透明度设置影响；头像自身的显示样式保留。此规则取代 #73 原正文的多段引导和新增入口方向，用户已确认效果并授权通过 Issue。

## 本地背景库（#70）

图库格子使用持久化的 512px 等比缩略图，仅可见区域附近按需读取；离屏卸载图片。选中候选才读取原图用于大预览/取景。缩略图不可用时可单独重试；原图预览失败也提供明确提示及重试，不因缩略图正常而隐藏错误。原图保存和删除当前使用中图片的规则不变。

2026-09-29 弹窗内参数编辑：右侧聊天预览下提供与外观页共用的适配、遮罩、模糊及单项恢复控件，以及“调整取景中心”入口。参数只写弹窗草稿，按图片版本分别保留，来回选图不丢本次调整；“应用背景”一次保存当前选中图片的参数并应用，其余未应用草稿丢弃，取消/关闭不保存参数。管理/替换子页不混入应用参数编辑。取景复用现有编辑器作为同一弹窗子页，“确认取景”仅回填候选草稿；取消/Escape 仅退出取景，回到预览并恢复入口焦点。外观页仍直接编辑当前背景。原图私有副本和显示参数分开保存的方式不变。

2026-09-29 用户确认沿用 #69 的图库管理语言。外观页保留当前背景缩略图与名称、“选择背景”“调整取景中心”“停用背景/重新启用”和直接可见的适配、遮罩、模糊参数。“选择背景”打开弹窗，宽屏左侧横向纯图片宫格、右侧复用 1920×1080 聊天预览，窄屏纵向排列，低高度内容可滚动且操作可达。缩略图裁切只用于浏览，不改变真实取景；名称用于悬停/无障碍和选中预览，不提供命名或重命名。

单击只选候选，“应用背景”才切换当前图片和每图参数，不修改颜色与透明度。“管理”进入独立多选，支持全选/取消全选、批量删除及单选替换；管理期间隐藏应用操作，退出后保留未删除候选。删除确认明确已有背景不受影响；替换先预览并明确保存，旧背景和取景保留，新图使用重置取景并保留该库条目的适配/遮罩/模糊。成功导入独立保存到库，不因关闭/Escape/取消应用而撤销；取消未保存替换仅丢弃临时图片。

停用保留可恢复的当前图片，恢复默认外观保留库及图片参数。删除/替换后当前背景可独立显示和重裁，只有再次应用其他图片时才释放不再使用的旧版本。该规则覆盖 #70 原先“删除当前背景后停用”及“不做批量管理”的远端要求；远端未修改。

## 本地头像库（#69）

2026-09-28 合并卡片：当前用户头像与头像库合为一张「用户头像」卡片，位于新助手默认值下方。顶部唯一「导入图片」入口打开选图与裁切，确认「保存到头像库」后持久保存并自动选中新图片，仍须点击「用作用户头像」才应用。取消导入不保存、不改变原候选。不再提供名称输入和重命名；内部沿用文件名（空名称回退为「头像」），仅用于悬停提示和无障碍识别。

头像库改为 64px 方形纯头像宫格，间距 6px，不显示常驻名称、候选文字或单图菜单。选中以细轮廓与角标表示，使用状态缩为小圆点并提供文字说明。「管理」切换为独立多选，支持全选/取消全选、删除所选，单选时可替换图片；「完成管理」退出并保留未删除的应用候选。管理选择不会应用头像，管理期间隐藏应用操作。批量删除显示数量并确认，已有用户/助手图片不受影响；失败整批回滚。助手选择器共用紧凑宫格和无命名导入，但不提供库管理。

后续布局调整：头像页统一使用一份页面标题和外层留白，新助手默认值、用户头像与头像库按 16px 间距紧凑排列，用户头像位于第二项，卡片内边距收紧。与外观页采用同一宽屏条件（至少 1440×700）：左侧配置独立滚动，预览固定在最右列；外观页预览纵向居中，头像页预览中心位于右侧区域从上往下三分之一处，随可用高度自适应；空间不足时优先完整显示预览，超出可用高度时从顶部滚动。窄窗口/低高度时预览回到顶部，配置纵向排列。不折叠配置，也不改变实际聊天头像尺寸或头像保存语义。

设置 → 头像保留当前用户头像、聊天预览、新助手默认头像及共享头像库。库入口常显，选中候选与正在使用状态分开。浏览/选择不应用，明确“用作用户头像”后生效。恢复默认保留库资源。导入 PNG/JPEG/WebP、最多 20 MB，沿用正方形拖动、缩放、定位和恢复居中；裁切后“保存到头像库”，取消不留半成品。具体顺序和紧凑宫格样式以上方最新约定为准。

管理模式提供替换及批量删除，不触发选用。替换只改变后续选用，已有对象保留旧图与独立裁切。从库中删除提示“已使用此图片的头像不受影响，仍可重新裁切”，不列出使用对象或要求解除引用；保留各对象的图片，不删除源文件。助手编辑使用共享库轻量选择器，内置默认与我的头像均先选候选，再明确使用回填草稿，保存助手才正式生效。导入裁切采用选择器内子视图，返回保留选择上下文；明确保存到库后取消助手编辑，资源保留，助手不变。

## 助手头像（#67）

2026-09-28：助手创建/编辑页的 Emoji 下拉改为图片预览、选图/更换、重新裁切和移除。复用用户头像的 PNG/JPEG/WebP、20 MB 限制与正方形裁切、拖动、缩放、位置滑块、恢复居中；“应用头像”只更新编辑草稿，“保存助手”才正式保存，取消不改原头像。内置系统、晴蓝、青绿、紫罗兰四个矢量头像作为默认选项；设置 → 头像可选择新助手默认值，只影响以后创建的助手。旧 Emoji 继续兼容显示。

侧栏显示该助手头像；助手消息左侧显示当前所属助手的 40px、10px 圆角头像，与正文间隔 8px、顶部对齐，正文和操作栏共用剩余宽度。2026-09-28 按用户反馈将聊天双方头像由 32px 放大至 40px，默认图标及旧 Emoji 同比例放大，侧栏头像尺寸不变。移除自定义图片或图片解码失败时回退该助手保存的默认头像。用户头像布局保持原约定。图片只在本机保存；不扩展为共享头像库。验证范围见开发指南，主观视觉效果及原生选图仍待用户确认。

## 用户头像（#32 / #34）

2026-09-28：设置新增「头像」，位于外观之后、关于之前。本轮只提供全局用户头像：选择/更换图片、重新裁切、移除，以及聊天效果预览。支持 PNG/JPEG/WebP，最大 20 MB；正方形裁切支持拖动、100–400% 缩放、横纵位置滑块和恢复居中，确认后应用，取消保留原头像。低高度窗口缩小裁切预览，保留操作按钮空间。

聊天头像为 40×40px、10px 圆角，位于用户气泡右侧，间隔 8px，顶部对齐；跟随宽/窄内容列。操作栏继续沿气泡右边缘对齐。2026-09-28 用户进一步确认：用户未设置图片、移除图片或图片加载失败时均显示默认人形头像，设置页预览同步；用户与助手头像同时显示，助手布局见 #67。用户气泡保留原有最大宽度限制，在极窄空间额外为头像留出 48px。

内置浏览器已检查浅/深主题、宽/窄窗口、裁切拖动/缩放、取消、重裁、刷新恢复、损坏图片和移除。鼠标按钮点击自动化未触发，操作使用键盘完成；裁切拖动实测通过。桌面原生选图和重启恢复、用户主观视觉效果仍待确认。后续头像库和助手头像不在本轮范围。

## 最新一轮问答与快捷键（#17 / #50）

仅最新一轮有多个候选时，在助手消息操作栏“分支”后显示 `‹ 2/3 ›`，不在用户消息重复显示。箭头同时切换提问与回答，提示为“上一版问答 / 下一版问答”；编号说明当前问答版本。生成、保存操作和消息编辑期间禁用切换，切换后恢复箭头焦点。继续下一轮仅保留选中问答，其他候选永久丢弃。

新消息 Enter / Ctrl+Enter 发送，Shift+Enter 换行；编辑消息 Enter 仅保存，Shift+Enter 换行，Esc 取消；编辑用户消息 Ctrl+Enter 保存并发送。输入法组合输入、重复按键及其他修饰键不触发提交。编辑发送与重新生成均免确认，删除仍确认。输入框占位及编辑提示显示快捷键；旧轮编辑发送提示截断后续历史。

## 透明度设置（Issue #59）

## 紧凑列表

适用于供应商下的连接等同类配置条目：字段能横向比较，操作集中在右侧，减少逐条卡片和重复装饰。

- 表头用加粗字段名，正文保持较轻的字重。供应商连接列表使用“连接名称 / 协议类型 / Base URL / 操作”。
- 名称、协议、地址分列对齐，表头与正文共用列宽规则；不要将名称、协议和地址挤在一小块区域，其余位置大幅留空。
- 条目之间用细分隔线，保留悬停和键盘焦点反馈。无需给每条数据额外加完整圆角卡片。
- 右侧管理和删除图标在各行保持相同位置与尺寸，不随名称或地址长度漂移。
- 长名称和地址可省略显示，但必须有查看完整值的入口。当前采用 `title` 悬停提示，进入详情也能查看完整地址；提示不代替按钮的可访问名称。
- 窄区域优先调整列布局：当前名称和协议在第一行，地址独占下一行；表头应同步调整。不要让长 URL 撑宽整个页面。
- 没有条目时给出明确空状态，并保留“添加连接”入口。

### 图标与操作语义

- 本列表的铅笔表示进入对应连接的管理详情，沿用原有跳转；整条主内容区域也可进入详情。这里不新增行内编辑模式。
- 删除为独立按钮，不应误触跳转。确认信息包含连接名称、协议、地址及连带删除的模型数量，便于区分同名连接。
- 浏览连接只改变当前详情，不改变助手默认模型或当前会话模型。
- 沿用现有生成期间禁用删除、未保存编辑确认和模型引用处理。样式调整不另加业务规则。
- 从供应商概览删除连接后，当前实现将焦点移回“添加连接”。

上述铅笔与删除约定适用于连接管理，不要求其他场景放弃自己的编辑或确认语义。
