调研日期：2026-09-27。Ayase 调研基线：`eec776370a8a01bd55d8291b4337c569189f59e9`，分支 `dev`。以下保留当时的研究与建议。后续用户已确认并授权两步命名：原文标题先显示，AI 成功再替换，失败保留原文，附件无正文用文件名。当前实施契约见 [ARCHITECTURE.md](../ARCHITECTURE.md) 的 Issue #31 节；下文的未实施表述、推荐单阶段方案与待确认选择仅是调研时状态。

## Issue 的实际边界

已读取 [#31 自动补充空白新对话标题](https://github.com/AyaseMinami/AyaseStudio/issues/31)：发送首条用户消息后，从该消息生成简洁标题；仅更新仍为“新对话”的对话；不覆盖手动命名、不随后续消息重复更新；失败保留原标题，不影响发送、导航和持久化。Issue 没有指定必须用 LLM，也未指定命名模型、长度及附件策略。

当前 [PLAN.md](../PLAN.md) 的旧范围仍将自动标题列为不支持，[ARCHITECTURE.md](../ARCHITECTURE.md) 也描述尚无此功能。#31 是待实施的新需求，本轮记录差异，未改动既有契约或远端 Issue。

## 其他工具的实现

Open WebUI 与 LibreChat 的一手源码调查见 [外部实现笔记](../ISSUE-31-EXTERNAL-RESEARCH.md)。以下是 Cherry Studio 当前 `main` 源码快照，不代表其所有已发布版本。

Cherry Studio，提交 `de2bc0aed0e805f1129e2ae7307a7af226f405c3`：

- 先从首条用户消息文字提取临时标题，空内容则跳过；有手动编辑标记或已有正式标题则跳过。[入口](https://github.com/CherryHQ/cherry-studio/blob/de2bc0aed0e805f1129e2ae7307a7af226f405c3/src/main/services/TopicNamingService.ts#L146-L166)
- 再把用户提问、文件名及助手最终正文组成摘要输入，单独请求命名。该路径检查命名开关、按对话加运行中锁，并在结束时释放。[摘要路径](https://github.com/CherryHQ/cherry-studio/blob/de2bc0aed0e805f1129e2ae7307a7af226f405c3/src/main/services/TopicNamingService.ts#L179-L229)
- 模型优先取快捷助手配置，再取聊天默认模型；不可用时还有其自身托管模型回退。命名不带原助手的工具配置，并显式设置无推理偏好。[生成与模型选择](https://github.com/CherryHQ/cherry-studio/blob/de2bc0aed0e805f1129e2ae7307a7af226f405c3/src/main/services/TopicNamingService.ts#L366-L425)
- 写回前重读对话，检查手动编辑标记和标题是否仍可自动命名，清洗结果后才保存。生成异常返回空结果，并通知命名失败。[写回保护](https://github.com/CherryHQ/cherry-studio/blob/de2bc0aed0e805f1129e2ae7307a7af226f405c3/src/main/services/TopicNamingService.ts#L449-L458)

这里借鉴的是行为与边界，没有复制 Cherry 的代码、提示词或资产。其临时标题、首轮问答摘要、托管模型回退都不能直接当作 Ayase #31 的既定需求。

## 可选方案与建议

| 方案 | 效果 | 代价和契约差异 |
| --- | --- | --- |
| 本地清理并截断首条文字 | 立即可辨认，无额外请求 | 对长问题只能取片段，不能概括语义；符合 Issue 允许截断的表述 |
| 独立 LLM 摘要首条文字 | 能概括长问题，更接近语义标题 | 每个符合条件的新对话增加一次请求，有延迟和费用；失败可严格保留“新对话” |
| 临时文字标题后替换成 LLM 标题 | 立即显示，后续更精炼 | 名称会变化两次；失败保留临时标题，与 #31 的失败默认标题验收不同 |

若目标是有意义的自动概括，建议第二种，保持 #31 的失败行为。初版可冻结首条消息发送时的连接与模型，用独立命名配置；需要便宜、快速的专用模型时，再明确增加全局命名模型选择。不能偷偷切换供应商，也不沿用聊天的系统角色、联网搜索、附件内容或任意 JSON 补充参数。

建议仅发送有上限的首条用户正文，不发送完整聊天；输出单行短标题，做空白、包裹符号及长度处理。中文长度和其他语言长度应单独验证，不能把“几个单词”当成中文字数保证。仅附件无正文时建议跳过并保留默认标题，是否使用文件名可另作产品选择。

触发时机建议在首条消息提交后启动独立后台任务，不等待主回复完成；这样不依赖主回复是否成功。代价是可能同时发出两条请求。若更在意并发限流，可改在主请求结束后执行，但必须明确首条回复失败/取消时是否仍命名；这些是待确认选择。

## 必须守住的写回条件

1. 按 conversationId 与首条 messageId 绑定任务，冻结命名输入和目标；切换对话不改变归属。
2. 保存一次尝试标记，阻止后续消息、重启、重新生成反复触发；不自动重试。异常保留现有标题。
3. 写回事务重新确认对话存在、消息仍有效、标题仍默认且未手动命名。删除、清空或手动修改后到达的结果应丢弃。
4. 不能仅比较标题字符串：用户手动命名为“新对话”仍应受保护。配置弹窗总会提交 title，修改模型但未编辑标题不应误判手动命名；需定义显式编辑意图。
5. 命名不占用聊天停止按钮或导航 busy 状态；需要独立取消与卸载清理。对新增字段采用兼容旧记录的默认规则；历史上手动设为默认名的行为无法从旧数据完美还原，应保守处理。
6. 名称与尝试标记通过仓库接口保存，标题刷新不切换当前选择、不重写消息或配置。模型输出只是标题文字，不执行其中指令。

## 后续实现验收

确定性测试应覆盖：首条只触发一次、后续/重试/续接不触发、手动改名与迟到结果竞态、手动同名、A/B 对话并发与切换、删除/清空、失败/超时/空结果、长中文与多行输入、附件无正文、重启后状态、数据库失败、命名与主聊天互不阻塞。使用假 transport，不为错误用例调用真实模型。
