## 1. 范围与原 Issue 的关系

- #80 原范围是扩大供应商原生搜索支持，本次改为 **Exa MCP 客户端外部搜索首版**。原正文保存在 Issue 的范围修订评论中。

## 2. 已确认的调查结论

详见同目录 [调查记录](../ISSUE-80-SEARCH-RESEARCH.md)。主要结论及来源：

1. Exa 托管 MCP 的官方端点为 `https://mcp.exa.ai/mcp`，支持匿名调用但有限流，支持 API Key/OAuth 的认证途径。首版采用匿名为默认、API Key 选填，不实现 OAuth。不承诺匿名无限额度或永久可用。[Exa 官方仓库](https://github.com/exa-labs/exa-mcp-server)
2. 远程服务执行搜索/抓取，客户端可以只增加网络协议适配和结果处理。Ayase 已有 Tauri HTTP 插件和 SSE 基础；无需启动本地 Exa 服务、打包 Node.js、安装浏览器引擎或建立通用工具运行时。包体、内存、延迟的增量必须在实现后测量，当前只是架构判断。
3. Cherry v1.9.13 的本地 Google/Bing/百度路径使用隐藏 Electron 窗口加载搜索网页、解析链接，再抓取正文，并非官方搜索 API。[旧版窗口](https://github.com/CherryHQ/cherry-studio/blob/da22fb797343fd3760e5dd2d467eda9bf0017632/src/main/services/SearchService.ts)、[网页搜索适配器](https://github.com/CherryHQ/cherry-studio/blob/da22fb797343fd3760e5dd2d467eda9bf0017632/src/renderer/src/providers/WebSearchProvider/LocalSearchProvider.ts)
4. Cherry 当前开发分支已移除上述本地适配器，以搜索服务 API/MCP 为主要外部路径；搜索与 URL 读取分开。PR #14443 的直接理由是后端已不支持本地服务、清理残留入口；公开 PR 没有 Google 警告的依据，最初后端移除的动机仍未知。[移除 PR](https://github.com/CherryHQ/cherry-studio/pull/14443)、[服务注册表](https://github.com/CherryHQ/cherry-studio/blob/c45058a31307231024d514f20bd5eca88fea2bfb/src/main/services/webSearch/providers/registry.ts)
5. Cherry 当前代码允许模型调整搜索词、多次调用，生成资料 ID 并解析引用。本次只借鉴职责拆分、来源映射和取消/错误处理，不采用它的完整工具循环、回退和 RAG 能力。[搜索工具](https://github.com/CherryHQ/cherry-studio/blob/c45058a31307231024d514f20bd5eca88fea2bfb/src/main/ai/tools/adapters/aiSdk/builtin/WebSearchTool.ts)、[引用解析](https://github.com/CherryHQ/cherry-studio/blob/c45058a31307231024d514f20bd5eca88fea2bfb/src/renderer/utils/message/citations.ts)
6. “DeepSeek 官方 API 一概没有原生搜索”不成立：当前 Responses 文档列出 `web_search` 被忽略，Anthropic 兼容接入文档则明确描述原生 Web Search。必须按端点/协议判断。[Responses](https://api-docs.deepseek.com/guides/responses_api/)、[Anthropic 兼容接入](https://api-docs.deepseek.com/zh-cn/quick_start/agent_integrations/claude_code/)

Cherry 仓库为 AGPL-3.0。本次只做源码静态研究，没有复制其代码、提示词、图标或资源；实现依据 Exa 官方接口资料独立编写。[许可证](https://github.com/CherryHQ/cherry-studio/blob/c45058a31307231024d514f20bd5eca88fea2bfb/LICENSE)

## 3. 设置与会话选择

### 全局：设置 → 网络搜索

新增独立分类，放在连接配置之后，沿用现有设置页标题、字段和按钮样式；首版只有 Exa MCP 配置卡，不列尚未支持的服务或空服务列表。

| 项目 | 建议行为 |
| --- | --- |
| 服务 | Exa MCP，首版唯一外部搜索服务 |
| 服务地址 | 默认 `https://mcp.exa.ai/mcp`；可修改、恢复官方地址；仅接受 HTTPS，禁止内嵌用户名/密码及把凭据放进 URL |
| API Key | 选填；留空表示匿名；默认遮罩；搜索凭据与聊天连接凭据独立 |
| 结果数量 | 默认 5，可选 1–10；客户端仍限制实际采用数量 |
| 保存 | 显式保存，持久化成功后才更新运行配置；失败保留草稿并提示 |
| 测试搜索 | 用户点击后发送一次固定公开查询，显示结果、限流、超时或协议错误；支持停止；打开设置/保存不自动联网 |

恢复官方地址不清空 Key；清空 Key 是独立显式操作。测试使用当前表单快照，成功不代替保存；测试结果不得回写聊天。测试区简短说明匿名限流，以及查询会发送给所配置的搜索服务。历史对话和附件内容不用于设置测试。

### 对话：输入区地球入口

- 地球入口提供 `关闭`、`模型原生`、`Exa MCP` 三项；明确显示当前选项，保留键盘操作、焦点恢复与无障碍名称。
- 旧会话 `webSearch: true` 且没有新字段时，继续解释为模型原生；旧关闭会话继续关闭，升级不能自动切成 Exa。
- 建议保留 `webSearch?: boolean`，新增 `webSearchProvider?: "native" | "exa-mcp"`，统一解析函数处理旧字段、未知值和无效值。助手只提供新对话的默认配置，已存在对话不跟随助手变化。
- 发送时冻结会话选择和全局搜索配置；生成过程中修改只影响下一次请求。不会同时启用原生和 Exa，不根据模型名称选择搜索路径。
- 外部模式对生成请求关闭原生搜索字段，关闭模式不发外部搜索。搜索专用模型自身可能始终搜索的既有提示仍适用。

## 4. 首版固定执行流程

```mermaid
flowchart LR
  A[发送并冻结配置] --> B[校验模型与必保上下文]
  B --> C[Exa 搜索一次]
  C --> D[归一化及限制资料]
  D --> E[重新计算最终上下文预算]
  E --> F[当前模型回答]
  F --> G[解析引用并保存来源]
```

### 查询生成和数据发送

- 首版搜索词直接使用当前用户消息的文本，去除首尾空白；不额外调用模型提取关键词，不把完整对话、系统提示词、附件内容或聊天 Key 发给 Exa。
- 为避免无提示改变意图，超长查询不静默截断。建议最多 2,000 个 Unicode 字符，超出时提示缩短；这是客户端建议值，需在编码时对照 Exa 当前工具 schema 复核。
- 只有附件而没有文本时，不猜测附件内容或制造查询，提示输入搜索问题或关闭外部搜索。
- 不把上一轮检索资料当作本轮新搜索结果。用户显式重新生成/重试时重新搜索一次，每个回答候选保留自己的来源快照；不会自动使用缓存结果冒充新检索。

### 与既有发送流程结合

保留 `useChatSession` 已有冻结模型/连接、生成任务锁、附件事务和会话隔离。发送前先完成配置与必保内容校验；提交本轮用户/助手消息后，在同一个生成任务中进入搜索阶段，再发模型请求。

- 搜索和回答共享一次发送的取消信号；同时搜索不同对话仍由既有任务管理隔离。
- 搜索开始后输入区允许编辑下一条草稿；本次完成不能覆盖较新的草稿或另一对话。
- 停止、删除、切换或晚到响应不得使失效任务重新请求模型或写错会话。继续使用原会话的 store 和任务身份，不以当前屏幕选中项作为写回目标。
- 全局设置冻结在内存，不保存到消息或 Anthropic continuation；不在网络诊断或错误消息中泄漏配置 Key。
- 外部搜索失败/取消/无可用资料时，不发送本轮回答请求，不自动改成普通回答。用户可关闭搜索后显式重新生成；保留本轮用户消息、附件和明确失败/取消状态。
- 初次自动命名不得因搜索失败而发模型请求：外部模式在成功搜索、完成最终预算校验后，才进入既有命名阶段。命名关闭搜索，不携带 Exa 内容或凭据。
- 保留既有 Anthropic `pause_turn` 的显式“继续”语义：续传冻结最终预算后的消息（包含本轮检索资料的请求副本、附件引用）、模型配置和同一来源快照，复用精确作用域的 provider replay，不重新搜索或读取新全局设置。不得把请求副本替换为原始用户正文；continuation 不含 Key、认证 header 或 MCP Session。显式重生成/重试才开始新检索。

### 状态与成功证据

- 在检索阶段展示“正在搜索 · Exa MCP”；结果成功后展示“已检索 · N 个来源”，回答继续展示生成状态。
- 检索成功和模型回答成功分别记录。搜索成功后回答失败仍保留已检索来源，不把检索状态改为失败。
- HTTP 200 不等于有搜索结果：必须完成 JSON-RPC/tool result 校验，并解析出可用来源。返回工具错误、无资料、只有无法识别的文本须明确区分。
- 全部来源无效等同无可用资料，阻止本轮回答；部分来源无效可以使用其余资料，展示实际采用数量和有界警告。

## 5. 模块与网络边界

建议新增 `src/search/`，持久化、传输和资料处理与 React 解耦；具体文件名可在编码时按现有惯例细化。

| 模块 | 职责 |
| --- | --- |
| 搜索设置 repository/controller | 独立版本化全局配置、校验、显式保存、冻结快照；UI 不直接读写 Dexie |
| Exa MCP adapter | 服务地址、认证、协议生命周期、JSON-RPC 请求/错误、JSON/SSE、工具结果解析、超时和取消 |
| 外部搜索准备模块 | 固定查询、资料预算、来源 ID、请求上下文副本、输出引用归一化；只有一个检索步骤 |
| 会话协调 | 接入现有生成任务与持久化队列；冻结配置、状态、失败和取消；不接管四协议适配器 |
| 现有 ChatTransport | 仍只负责聊天协议；接收已准备好的中立消息，保持 Responses `store:false` |
| 现有 SafeMarkdown/SearchResults | 显示归一化来源与引用，继续走安全 Markdown 和受限外链 |

首版只固定调用 Exa 的 `web_search_advanced_exa`，使用 `query`、`numResults`、`textMaxCharacters` 三个参数。选择它是为了获得可按 JSON 解析的结果边界；不提供高级筛选、摘要生成、subpages 或额外搜索词，不加载插件、不暴露任意工具、不启动 MCP 子进程、不调用 Exa Agent 或 URL 抓取工具。它在一次搜索中提取有界正文；独立 URL 抓取不是首版范围。

### MCP 接入要求

- 固定有限适配器不意味着跳过协议要求。完整执行 `initialize`、版本/能力核对和 `notifications/initialized`；后续携带协商版本及服务返回的 Session ID，不能只抄 Cherry 的单个 `tools/call` POST。只接受客户端明确支持的协议版本。
- `tools/list` 如用于确认固定工具/schema，仅限首次显式测试/搜索中的协议准备；不在启动时探测，不让远程清单扩展可执行工具。
- 设置测试与实际搜索共用地址解析、参数、认证和结果解析。正常聊天模式不触发 Exa 初始化。
- 设置展示的默认基础地址仍为 `https://mcp.exa.ai/mcp`；同一地址解析函数为所有协议请求设置固定 `tools=web_search_advanced_exa` 参数（替换同名参数），不能通过配置地址开启其他工具。官方 README 明确给出该工具选择方式；部署是否对匿名开放须真实验收，不静默换成另一工具。
- 支持服务返回的 JSON 或 SSE，按请求 ID 匹配终态，忽略无关通知；拒绝未知请求、`isError`、缺失终态、错误 ID、畸形数据和无界响应。SSE 分块、CRLF、UTF-8 跨块、最终尾事件需要测试。
- 首版只支持 Exa 所需的远程 HTTP 方式，不实现历史 SSE 端点自动降级、OAuth 或多协议试错。版本/端点不兼容时报错，由用户修正。
- Key 使用官方支持的认证 header，不把 Key 拼 URL；聊天 Key 永不发送给 Exa。跨地址重定向不得携带凭据，也不自动跟随到未配置服务。
- 建议检索总超时 30 秒（覆盖协议准备），响应正文上限 2 MiB；取消/超时后关闭读取并释放 reader，按协议尽力发送取消通知。释放 Session 的操作不能延迟本地停止或覆盖原错误；不承诺服务端已停止。限流/网络/服务器错误不自动重发；Session 过期不自动重放已发出的搜索。此约束只覆盖 Ayase，自身调用一次不能保证 Exa 服务内部没有重试。
- 本次固定 Exa 源码版本为 `f3d71fb6b0ff4b4683f108f05bc2bae61a9f7e97`（包版本 3.4.1）。普通 `web_search_exa` 返回 `Title:`、`URL:` 等格式化文本：摘录可包含相同字段/分隔符，严格 URL 校验仍不能可靠区分真假条目，故首版不采用此文本解析路线。[普通搜索源码](https://github.com/exa-labs/exa-mcp-server/blob/f3d71fb6b0ff4b4683f108f05bc2bae61a9f7e97/src/tools/webSearch.ts)
- 选定的高级搜索工具在 `content` 文本块中返回 `JSON.stringify(sanitized)`，不是 MCP `structuredContent`。显式传 `query`、用户设置的 `numResults` 和建议每条 1,500 字符的 `textMaxCharacters`；不省略正文上限。只接受受支持的文本块组合，先按 MCP 校验，再 JSON.parse 并校验 `results` 数组及白名单字段；来源只从数组条目提取，摘录中的假头/URL/JSON 字符串始终是数据。[高级搜索源码](https://github.com/exa-labs/exa-mcp-server/blob/f3d71fb6b0ff4b4683f108f05bc2bae61a9f7e97/src/tools/webSearchAdvanced.ts)
- 无结果普通文本、空 JSON 结果、`isError` 和未知格式分别处理；识别官方固定无结果文本只用于无结果状态，不从普通 prose 猜来源。sanitizer 可能省略空数组，因此缺少 `results` 的 JSON 不能假定成功：首版按无可用资料/无法确认格式明确阻止，并记录契约差异。所有情况都限制块/字段/数量/总大小，保留至少一条有内容的有效资料才成功。
- 线上输出若与固定源码不同，须记录差异并明确调整受支持格式；不自动换工具、回退普通文本解析或猜测完整网页内容。JSON 只能维护字段边界，不能证明网页内容真实或消除提示词注入。

## 6. 资料预算、引用和安全

### 请求副本

- 每条资料归一化为稳定且只属于本次回答的 ID、标题、HTTP(S) URL、有限摘录；按规范化 URL 去重，保持结果顺序。
- 建议资料总量最多 8,000 Unicode 字符（包括合理分摊的摘录），标题/地址另有长度上限；在最终协议输入预算内还要进一步约束。最终数值不是匿名额度或供应商承诺。
- 系统指令和用户原文、附件、已有正文不改写。检索资料作为独立标识的外部数据，加入 **本次最新 user 消息的请求副本**；不创建假的 assistant/tool 消息，不提高为 system/developer 指令。
- 跨协议使用普通文本上下文，使不支持 Function Calling 的聊天模型也能使用。原始用户消息仍按现有内容保存/复制。
- 资料、引用说明、附件和历史一起计入最终 `contextBudget`；重新按完整轮次决定历史保留。先限制资料，不能突破必保内容规则或将资料插入预算计算之后。
- 保留至少一条有可用内容的资料；预算无法容纳必保内容和最小资料时明确阻止，不在搜索开启时静默丢弃全部资料继续回答。
- 本轮资料只用于本次请求；后续请求恢复普通对话文本，不自动再次发送旧资料全文。旧引用标记转换成来源标题/URL 的普通上下文，避免历史中的内部 ID 造成误引用；再次联网生成只允许引用本轮提供的 ID。
- 完成本轮后，普通后续请求对外部搜索回答使用上述文本投影，忽略其 provider replay 的请求副本，避免旧内部 ID/资料通过 replay 重入上下文；原生搜索既有 replay 行为保持不变。这不影响尚未结束的显式 pause/resume。

### 回答和引用

- 独立设计 Ayase 专用引用标记（示例 `[ayase-source:<id>]`），随资料给模型解释；示例格式不是照搬 Cherry 提示词。只解析当前回答对应的真实来源 ID。
- 代码、行内代码和公式里的相同文本不转成引用；未知 ID、未闭合流式片段或没有标记时不编造角标。
- 保留模型原始 Markdown。AST 渲染时将合法标记转换为现有来源角标，并为保存的原文建立一致的 UTF-16 定位；普通复制/导出将已验证标记转换为可读编号或来源链接，不暴露内部 ID，也不改变数据库原文。
- 流式阶段仅发布已完整识别的引用，终态再校验一次；引用偏移随中文、CRLF、重复句、Markdown 转义与候选版本正确保持。
- 没有合法正文引用时仍显示来源列表，并说明“已检索资料，正文未提供有效引用”。来源数量不当成被实际采用或已验证事实数量；ID 存在不能证明结论被来源支持。
- 外部资料是不可信数据，不能覆盖系统/用户指令、触发工具或请求读取本地文件。按结构编码，避免文本关闭分隔符后混入指令；任何文本封装都不声称能完全消除提示词注入。
- 结果和模型正文不注入 raw HTML，来源按钮复用现有 HTTP(S) 外链检查。非法 URL 不可点击，不从模型自述或普通链接制造检索成功状态。
