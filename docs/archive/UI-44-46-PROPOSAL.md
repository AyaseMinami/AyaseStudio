## 最终确认与实施范围

- #44 为共同视觉方向与最终一致性检查；#45 聊天页、#46 外观页、#47 连接管理页连续实施。
- 保留既有助手 → 对话级联与宽屏让位、窄屏覆盖规则，保留悬浮面板、外部间距和阴影，外框圆角降为 8px，不改为贴边平面或 Tab。
- 默认强调色试用浅蓝（浅色 #60A5FA、深色 #93C5FD），用户消息继续跟随强调色，自定义值保持。
- 圆角按控件角色调整，不禁止所有圆角；消息、输入框和弹窗保留圆角，优先消除重复卡片和边框。
- 消息操作常显低强调图标，保留名称、提示、键盘焦点和执行状态。
- 外观页取消断线标题外观，使用独立标题与设置行，主题单选保留原生分组语义。
- #47 采用供应商 → 连接渠道的两级导航，模型仅在右侧连接详情中管理，展开与查看详情分开。右侧随节点显示管理内容，查看连接不改变助手默认或聊天模型；原管理、目录、测试、排序操作保留。
- 用户要求避免过度防御编程和全量测试；采用定向回归、前端构建与内置浏览器验收，不使用原生桌面自动化、不调用真实供应商。
- 不提交、不推送、不修改或关闭远端 Issues；代码完成与用户主观视觉验收分开记录。

## 1. 设计目标

Ayase 是本地优先、多助手、多协议的桌面聊天工作区。推荐方向是：**连续工作面、清楚的操作层级、适合长文阅读、少量品牌色、可控的个性化**。

不把“现代 PC”理解为全直角、满屏高密度或禁止气泡。导航可以紧凑，正文仍需宽松；工作区尽量平整，弹窗、菜单、编辑器和需要遮挡背景的内容可以有明确边界。

## 2. 对外部建议的审视

| 建议 | 判断 | Ayase 的处理 |
| --- | --- | --- |
| 去掉侧栏浮动卡片和重复边框 | 仅内部减法成立 | 保留级联悬浮面板，降低外框圆角；不为每行再画框 |
| 大幅收敛圆角 | 成立，但不能机械全局替换 | 按控件角色建立少量尺寸；圆形图标、颜色样本不在禁止之列 |
| 用户气泡是 9999px 胶囊 | 与当前代码不符 | `App.css` 为 `1rem 1rem 0.3rem 1rem`；问题是饱和色、尺寸与视觉重量的组合 |
| 紫色本身廉价，绿色天然最护眼 | 不采纳这种归因 | 这是主观评价，不能当作科学或行业规范；先控制面积、明暗与对比度，再选择色相 |
| 强调色占比不能超过 5% | 可作克制用色的提醒，不能作硬指标 | 验收具体元素：用户气泡不用实心强调色，选中行不整块深色，装饰不抢正文 |
| 合并助手和对话为 Tab | 属于信息架构变更，不是样式修补 | 暂不纳入；会隐藏助手—对话的同时可见关系，并改变 #27 交互合同 |
| 删除 fieldset/legend | 删除断线外观成立，删除语义不成立 | 移除分组边框；原生 radio 组保留 fieldset/legend 或等价可访问分组 |
| 所有操作仅 hover 显示 | 不完整 | 同时支持 focus-within、键盘与无 hover 设备；忙碌、错误、停止/继续入口保持可见 |
| 所有设置永远左文右控 | 适合简单设置，不适合全部内容 | 宽屏简单行用此布局；背景预览、取景编辑及窄窗口可上下排列 |
| 输入框应向底部移动 | 当前已有 20px 底部留白，不能凭描述判定错误 | 先减阴影和重复表面，再按真实窗口检查底距与输入区自增高 |

W3C 明确推荐用 fieldset/legend 为相关表单控件分组，语义与边框样式应分开：[Grouping Controls](https://www.w3.org/WAI/tutorials/forms/grouping/)。

## 3. 推荐视觉规范（#44）

### 表面与边界

- 常驻导航和工作区：平面连接、0 圆角、无阴影；面板之间最多一道必要分割线。
- 列表：默认无边框，选中用浅背景加字重/标记，悬浮比选中更轻，不能只靠颜色识别。
- 表单：外置标题、连续设置行、组间留白。默认不用“整页大卡片 → 分组卡片 → 字段卡片”的结构。
- 输入框、菜单、弹窗、代码块、背景预览是有实际边界的对象，可以保留框线。阴影主要用于浮层；窄窗口覆盖导航可保留边缘分离效果。

### 尺寸起点

| 角色 | 建议值 | 说明 |
| --- | --- | --- |
| 常驻面板 | 0px | 区域分隔不靠圆角 |
| 列表行、普通按钮、表单控件 | 6px | 常规控件高 32–36px，列表行 34–38px |
| 用户消息、思考区域、代码块 | 8px | 长文局部滚动，不能撑坏工作区 |
| 输入编辑区、弹窗 | 10px | 允许功能性容器，无大面积浮动阴影 |
| 小图标 / 命中区 | 16px / 28–32px | 图标视觉尺寸不等于按钮可点击尺寸 |
| 间距 | 4 / 8 / 12 / 16 / 24 / 32px | 导航紧凑，正文段落与设置组适当留白 |
| 字体 | 正文 16px，UI 13–14px，辅助 12px | 不为增加密度压缩正文；中英文、代码分开校验 |

这些是设计起点，不是跨所有尺寸生硬套用的最终数值。

### 颜色

推荐先保留 Ayase 的冷紫识别，候选强调色浅色 `#5E6AD2`、深色 `#9AA4F2`；它们是待视觉验收的候选值，不宣称“行业统一高级色”。另用中性灰方案做比较，无需因为竞品而换成绿色。

- 用户消息改中性浅灰/深灰底，文字用对应主题正文色；不再随强调色整块着色。
- 强调色主要用于主操作、焦点、活动工具和小型选中标记。降低装饰对比度，不降低文字可读性。
- 助手回复保留现有背景色及透明度自定义。此次不擅自将默认透明度改为 100%，也不抹掉已保存的外观偏好。
- 自定义强调色、画布色、助手气泡色继续经过现有安全派生；需要解除 `deriveAppearance` 中强调色对用户消息背景的绑定，而非在 CSS 尾部强行覆盖。
- 新默认色只影响“跟随主题”的值；已保存的自定义值保留。用户气泡与强调色解绑是明确的显示行为调整，要同步设置说明。
- 文字以 4.5:1、必要非文本控件以 3:1 为校验目标；照片背景需测试实际叠加结果，不能只验纯色 token。依据：[文字对比度](https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum/)、[非文本对比度](https://www.w3.org/WAI/WCAG22/understanding/non-text-contrast.html)。

### #44 建议完成条件

- 用户确认聊天页和外观页的浅/深色代表图后，冻结共同视觉规则。
- 建立小规模语义尺寸/表面规则，排查导航、普通按钮、弹窗、提示与错误态；不引入大型设计系统或新组件库。
- 共享规则的实施以 #45、#46 的真实页面为驱动；其他设置页仅做受共享样式影响的回归，不趁机重设计模型服务页面。
- #44 作为统筹 Issue，在 #45、#46 与跨页一致性验收完成后关闭；不重复承包两页全部工作。

## 4. 聊天页（#45）

### 布局与导航

保留主导航 + 助手栏 + 当前助手的对话栏 + 聊天主体。保留两张悬浮面板的外部间隙、细边框和阴影，仅将外框圆角从 12px 降为 8px，标题与创建入口放在紧凑的面板头。

助手栏建议约 176–192px，对话栏约 208–224px，最终结合长中文名称验证。已有宽屏让位（>1100px）、窄屏覆盖、<=860px 初始隐藏、分级 Escape、点击正文不自动关闭和选中对话后保持展开继续有效。导航收起时隐藏区域不能获得焦点。切换布局不能移动菜单到错误层级。

不自动合并两个列表，不新增搜索、置顶、收藏或文件夹。长名称省略但可获取完整名称；保留当前选择、菜单和后台生成提示，不能为清爽隐藏 #53 的任务状态。

### 消息和编辑区

- 保留用户右对齐、助手左对齐；用户消息用中性背景、8px 圆角，长代码和公式在内容内部滚动。
- 助手回复减少外框感，默认底色弱化与否结合现有气泡设置验收；自定义和照片背景下仍有可读承载面。
- 思考摘要用简洁的展开行及必要细分隔，不在回复内部再包厚重卡片；错误、未完成、暂停与停止状态仍有明确文字。
- 消息操作改图标，推荐先保留原有五个操作的直接入口，避免本次额外增加“更多”菜单状态机；分组 hover、focus-within 时显示，无 hover 设备保持可见。
- 操作区预留高度，显示/隐藏不引起正文跳动。操作有可访问名称、hover/焦点提示，复制结果和失败反馈保持可见；停止、继续生成不能隐藏于 hover。
- 输入区与消息列共用宽度，保留 48rem 阅读模式与展开模式。圆角 10px，移除大阴影，底距以 16–20px 为起点；多行输入和错误提示不能挤出发送按钮。
- 保留已确认的紧凑附件标签、移除操作、完整名称提示及多附件换行，不恢复草稿大缩略图。

### #45 验收

- 浅色、深色、照片背景分别检查短消息、长 Markdown、表格、公式、代码块、附件、思考和生成失败。
- 1440×900、1280×800、720×520，以及 125%/150% 缩放检查布局；除预期的局部代码/表格滚动外不出现页面横向滚动。
- 对比导航全开、只开助手、全收起；维持既有宽窄窗口行为，正文可直接操作，焦点与 Escape 顺序正确。
- hover 与键盘逐项访问五个消息操作；覆盖流式、后台会话生成、停止、暂停继续、编辑保存、编辑并发送、重新生成和分支。删除/截断原有确认保持。
- 改变主题/导航不丢当前草稿、选中会话或生成状态。不得自动请求模型或改变消息存储语义。

## 5. 外观页（#46）

推荐采用“分组外标题 + 无外框的设置行”，而不是重新给每组套一个大白卡片。设置内容宽度建议上限 800–880px；宽窗口也不把滑块拉满。

顺序如下：

1. **主题模式**：一行三段选择“跟随系统 / 浅色 / 深色”。保留原生 radio 语义和键盘行为，不做三个巨型选中卡片。
2. **界面配色**：强调色、画布背景两行；左侧名称与短说明，右侧 28–32px 色样控件及必要的当前状态。保留现有回到主题默认的入口与范围。
3. **助手回复**：背景色、背景透明度两行；透明度值紧邻滑块。继续使用“0% 不透明、100% 完全透明”，不能把 transparency 与 opacity 反转；颜色跟随主题只重置颜色，不暗中重置透明度。
4. **聊天背景**：选择/替换图片、移除、适配方式、遮罩、模糊、取景中心。无图时，依赖图片的控件禁用并解释原因；加载错误与忙碌态不消失。
5. **效果预览**：紧接相关控制，显示模拟用户消息、助手消息及思考/代码局部，检验整体而非只显示装饰色块。取景功能仍使用现有与真实画布一致的比例逻辑。
6. **恢复默认**：页面末尾单独低强调区域，说明作用范围；保留现有恢复行为，不扩展为删除用户源图片。

设置说明面向使用者：例如“用于主要按钮和选中提示”，不向用户讲 CSS 变量、安全表面派生等实现细节。保留“图片仅保存在本机，不上传”、格式/大小限制和不删除源文件等有实际决策价值的说明。

窄窗口时控件移到说明下方，值与滑块保持同组，不强行左文右控。错误和可读性提示靠近相关设置。

### #46 验收

- 所有现有设置有一一对应的新位置，无功能遗漏；即改即生效、重启恢复、系统主题变化均正常。
- 自定义颜色、色值回退、背景透明度端点、恢复颜色默认和整体默认分别验证。
- 保留图片选择/替换/移除、cover/contain、遮罩、模糊、取景、缺失图片回退、错误与 busy 状态。
- 键盘可选择主题、操作颜色及滑块；分组有可访问名称，焦点始终可见。图标小不等于缩小命中区，项目优先采用 28–32px，参考 [WCAG 2.2 最小目标尺寸](https://www.w3.org/TR/WCAG22/#target-size-minimum)。
- 以与聊天页相同的主题、尺寸、缩放矩阵验收，背景实际读写仍需桌面验证。

## 6. 落地顺序和代码边界

1. 本提案与交互示意评审：先确认整体方向，不先大规模改 CSS。
2. #44 规范首版：明确颜色角色、圆角、边界和字体；共同规则跟随两页开发，不单独制造抽象框架。
3. #45：先面板/消息/输入区视觉，再操作栏显隐与可访问性；不改 generation、repository 或 transport。
4. #46：按新行结构重排现有控件，复用 AppearanceController 与 BackgroundImage/取景能力。
5. 跨页统一复查后完成 #44；实际修改公开接口、状态机或存在未解疑点时按仓库要求独立审查。

主要落点：`src/App.css`、`src/appearance/appearance.ts`、`src/ui/chat/MessageList.tsx`、导航与 ChatWorkspace、`src/ui/settings/AppearanceSettings.tsx`。尤其注意 `appearance.ts` 中强调色到用户消息的绑定、App.css 的多处覆盖规则和设置页旧文案必须同步。

行为变化用确定性组件/主题测试覆盖，不写仅复述 CSS 数值的测试。实施时运行仓库默认代码 gate；原生窗口、图片与主题首屏变化执行 Tauri 烟雾测试。视觉验收须有真实页面与用户主观评审；构建通过或示意图好看均不等于应用通过。

保留 ARCHITECTURE 的级联悬浮面板约定、外观颜色合同，以及 DEVELOPMENT 的新验证记录；PLAN 只记录最终批准的范围。本轮不提前把提案写成已实现事实。

## 7. 推荐拍板点

- 采用级联悬浮双栏，暂不引入助手/话题 Tab；若用户希望减少常驻栏数，另行明确导航状态与助手切换方案。
- 推荐用户消息与强调色解绑，改为中性背景。
- 推荐保留冷紫为小面积默认强调色，示意可比较中性主操作；最终颜色由浅深主题代表页决定。
- 推荐外观页使用无框分组和细分隔行，避免“为了去卡片又设计另一层卡片”。

这四项是本方案的推荐决策，尚未获得用户确认；其余尺寸是可以在实际页面微调的局部设计选择。
