## 后续修订：Exa API 与 MCP 独立配置

用户明确选择 Exa API（必填 Key）＋ Exa MCP（Key 选填）两条接入。设置页两张卡分别保存地址、Key 和结果数量，各自测试/停止；保存当前卡不覆盖另一卡的已保存配置或未保存草稿。聊天与助手地球入口提供关闭、模型原生、Exa API、Exa MCP 四项，显式选择后仅使用对应配置，无自动切换或回退。API 保存、测试和发送前检查 Key 与地址；直接发送一次 `/search` JSON 请求，合同见 [官方文档](https://exa.ai/docs/reference/search)，未复制 Cherry 实现。

本机搜索配置升为 version 2，包含 `exaApi` / `exaMcp`；旧 version 1 地址与 Key 只迁入 MCP，读取不写入或启用 API。两种搜索复用预算、引用、来源与历史逻辑，暂停/继续绑定原服务快照。新备份 document v3 包含两套配置并保持 v1/v2 读取：旧 v2 替换仅覆盖 MCP，保留本机 API；v3 替换覆盖两套配置，缺失凭据分别保留本机 Key；合并/副本保留本机两套全局配置。加密 envelope 与事务日志不变。

独立 Sol/high 审查发现完整 v3 替换依赖损坏的本机搜索配置，已修复为含两套配置/凭据时直接采用备份内容；42 项恢复回归确认失败回滚保留原始损坏数据，重试可修复，独立复核通过。其余当前变更未发现具体缺陷。API 与 MCP 的确定性测试覆盖独立 Key、服务分流、单次请求、限流/畸形/无结果、取消和超时；两种模式均通过四协议生成、预算及 Anthropic 继续测试。下方 1049 项验证和 MCP-only 描述属于首次实现快照，后续最终结果见本节及开发指南。

浏览器隔离合成数据检查了 API 缺 Key 阻止测试、两卡保存与草稿隔离、MCP 空 Key、各卡测试和停止；重新加载保留两套结果数量和独立配置。浅深主题宽窄视口与聊天四模式、API 检索/引用展示使用模拟边界。原生隔离程序再次编译启动；未执行真实 API/MCP、模型或凭据探测。

## 首次 MCP-only 实现快照

- 设置 → 网络搜索：Exa MCP 独立地址、选填 Key、1–10 条结果；显式保存，恢复地址保留 Key，清空 Key 独立操作；固定公开问题测试当前草稿并可停止。打开/保存不联网，损坏设置可显式使用默认草稿修复。
- 会话与助手提供关闭、模型原生、Exa MCP 三项。旧 `webSearch:true` 保持原生；当前请求冻结配置。Exa 模式关闭四协议原生搜索工具，Responses 保持 `store:false`。
- `src/search/exa.ts` 有限 Streamable HTTP 客户端只调用固定 `web_search_advanced_exa`；执行初始化、版本与工具/schema 核对，支持 JSON/SSE、Session/版本 header。查询只含本次用户文本，Key 与模型连接分离，无重试/自动回退。30 秒总超时、2 MiB 单响应和有界资料；取消释放读取并尽力清理会话。
- 搜索先于回答和自动命名；检索失败、取消、无结果或最终预算不足均阻断。资料只加入最新用户消息的请求副本并参与最终预算，不改写系统指令、用户原文或附件。已获取的来源状态可独立于模型失败保存。
- 保存查询、来源和有界摘录，展示来源列表和有效引用角标。Markdown AST 只转换当前来源 ID 的合法文本引用，跳过代码/公式/转义/未知 ID；中文、UTF-16、CRLF、列表和嵌套引用块保持定位。复制转换成可读来源链接；后续历史不回放旧资料全文或内部 ID。Anthropic 显式继续复用原请求资料，不再次搜索。
- 搜索快照随候选/分支保存，编辑、重生成、并发会话与取消隔离。备份 document v2 包含搜索设置、Key 和新快照，仍接受 v1；加密 envelope v1 不变。v1 及 v2 合并/另存副本保留本机搜索设置，v2 替换按预览应用，纳入事务回滚；缺失凭据不抹掉本机 Key。加载/恢复不联网。
