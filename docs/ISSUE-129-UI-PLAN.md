后续对齐修正：常规页标题与分组统一最大 1000px，连接/外观页与共享规则统一顶部留白 24px、窄窗 20px；不改变卡片结构或滚动。浏览器 2560×1380 下常规标题和四分组左右边缘均为 718/1718，720×520 下均为 72/684；连接、外观、搜索、数据页标题顶部均为 68px。截图 `general-aligned.png` 保存于本轮修订证据目录。

首轮“搜索平铺服务分区”和缩小外观右侧预览未获用户接受：搜索小卡片与外观大预览是有意保留的设计，用户还指出独立滚动习惯被改变。修正为恢复搜索原卡片网格、标题及常规/数据/关于的不透明底板；保留共享字号与控件尺寸。外观宽窗左右独立滚动，左栏 `clamp(26rem,32%,40rem)`，剩余宽度给右侧大预览；中等窗右侧也更宽，窄窗全部内容通过页面滚动访问。

本轮只改展示 CSS 和设计记录，未改变任何回调或数据。70 项定向测试通过。浏览器在 2560×1380、1440×900、720×520 检查；使用隔离合成背景复核底板，不读取用户背景库或密钥。1440×900 下左栏 clientHeight 663、scrollHeight 1758，键盘访问末尾 scrollTop 1095，外层 scrollTop 保持 0；绘图参数在 720×520 下可独立滚到 scrollTop 324。连接树/详情均保留 `overflow-y:auto`；空任务列表仅确认滚动容器，未声称满队列实机验收。证据位于 `.impeccable/review/129-revision/`。新独立审查对本次修正未发现可操作缺陷；最终仍待用户继续验收，不沿用首轮观感通过的结论。

用户认为聊天工具重排不便，因此 Composer 工具位置不动；消息操作继续常显、直接点击，不移到更多菜单。助手/对话导航和收起规则保留。绘图接受布局改善，设置六页为本轮主要重做范围。现有保存/取消、快捷键、凭据、数据、请求、队列及删除保护不改变。

## 设计契约

模式：Operate（长期使用的桌面工具），聊天正文兼顾 Read。保留系统中文字体和用户主题、背景、头像、气泡及可选玻璃；静态工作面用一层边界，不叠重投影。使用现有语义颜色，主题色只突出选择和主行动。

字号：标题22px、分组16px、界面14px、辅助13px、元信息12px、消息15px，沿用相应语义变量。控件36px，分组间距28px，内部间距8/12/16px，页面横向留白20–40px，面板12px圆角。焦点、错误、禁用与强制颜色保留。

design-taste-frontend 抽样：achromatic-ledger，seed 51954421；采用安静表面、清楚对齐与分组行。按用户既有选择保留主题色按钮、壁纸和局部玻璃，覆盖抽样中的纯黑白/禁玻璃建议。无更换字体、Logo或新图片素材。impeccable 采用代码实现的应用工作区流程；本轮之前的明确问答已确定产品与设计边界，不重复采访。

首屏目标：设置页能看到标题、当前分组及可操作的设置；外观页能同时看到调整与效果；绘图能找到生成动作并保留大图区域。产品特征是个人可定制的聊天阅读与本地绘图，不添加仪表盘指标或营销装饰。

## 实施分工与顺序

1. 主代理负责共享设置规则、常规/连接/搜索/数据/关于页、确认字号修复和文档。各页面保留原 callbacks，结构变更只调整展示层。
2. 独立工作单元负责外观：宽屏左控件右预览，窄屏控件优先，整体预览加实际字号阅读样本，全部现有字段继续可达。
3. 独立工作单元负责绘图：配置滚动体与生成操作区分离，任务区域有界，低高度/窄宽度保持可达。不引入新视图切换状态或业务规则。
4. 主代理整合，在隔离浏览器检查六设置页、聊天和绘图；使用合成状态和模拟原生边界，不读取真实数据或密钥。
5. 运行定向组件测试、npm run check、cargo check、diff检查。独立审查代码、交互约束与截图，修复实际问题。
