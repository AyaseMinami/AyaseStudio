## 行为

- 初始大于 860px 显示 64px 头像列与 240px 对话栏，不超过 860px 整体隐藏。点击当前助手，或成功切换到其他助手，展开完整助手列。用户体验后将直接主键／触摸点击收缩扩大到整个聊天区的正文、空白与输入工具区；顶部栏与左侧导航排除。普通 focus、blur、Tab、窗口失焦、纯滚动及弹层内部仍保持状态；详见后续体验修正。
- App 持有三个独立运行时状态：整体显隐、助手展开、对话栏显隐。页面切换保留状态，整体关闭后恢复上次形态；不新增持久偏好。收起对话栏显示完整助手；Escape 优先处理菜单、对话框、拖动或删除确认，再关闭对话栏与整体导航。
- 大于 1100px 按实际宽度退让，不超过 1100px 覆盖。宽度、对话栏位置与聊天边距约 200ms 同步过渡，尊重减少动态效果。列表保持挂载；固定行高与工具区高度，计数不换行，避免动画期间滚动范围变化。隐藏管理按钮与把手 inert 且不参与 Tab，保留头像菜单和现有 6px 拖动阈值。
- 新助手名称为空、必填并优先获焦；支持重名，沿用现有配置和单次创建命令。打开草稿时分配最终 ID，取消不创建记录。自动头像使用裁剪空白后的首个完整 Unicode 字符组合、英文首字大写和按 ID 派生的稳定底色；图片、Emoji 与显式旧内置头像保持显示。选择候选后明确应用，保存才更改助手。

用户授权先实施正文缓存与导航局部订阅。`App` 持有稳定的内存控制器，只有导航组件订阅三个布尔状态；无变化的命令不发布新快照。纯导航操作不再重渲染 `ChatWorkspace`、`MessageList` 或 `Composer`。`SafeMarkdown` 使用默认浅比较，同时检查正文和完整不可变搜索记录，保留原有安全渲染、公式、代码块与引用行为。宽窄切换仍可重渲染消息列表，但不再重复解析未变化的正文。没有改动动画 CSS、失焦规则、退让边界、持久数据或供应商协议。

dev 的 StrictMode 样例虽然同样消除了上述历史正文解析与导航的聊天区重渲染，仍测到约 100–182ms 脚本耗时和 125–187ms 最大帧间隔；开发构建仍有额外成本，本轮不声称桌面卡顿完全消除。宽度／位置／边距动画仍会触发布局。若用户复测仍卡，再对剩余导航渲染与动画布局分别测量；消息列表的其他算法调整未纳入本轮。诊断与最终原始数据位于忽略目录 `.navigation81.local/perf/results.json`、`results-final.json`，不包含实际聊天内容或凭据。
