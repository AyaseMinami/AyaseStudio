## 3. 交互草图与主要流程

可直接打开 [离线交互草图](design/drawing-workspace-83.html)。图像为代码绘制的合成示例，任务由手动模拟事件推进；无网络、API Key、真实文件选择、应用数据库或供应商请求。草图展示候选布局，不是已经接入 Ayase 的功能。草图的 500ms 提交禁用窗口只模拟提交忙碌；正式实现须使用提交令牌及持久化提交完成状态防重，不能以固定延时代替持久化门禁。

应用左侧主导航增加“绘图”，与“聊天”同级，设置仍为共同入口。绘图内部有“生成 / 任务 / 成果库”三个视图，共用当前草稿、队列与选中成果。模型选择只显示绘图连接下已添加模型，不在此获取目录。缺配置时提供“前往设置”，保持草稿；不存在默认供应商或自动替换模型。

生成页：宽屏左侧提示词、参考图和协议参数，右侧至少保留一个常驻大图预览窗口，最新生成并保存成功的图自动显示；下方横向历史缩略图用于切换这个窗口中的图片，不弹预览窗。预览等比完整显示、不裁切，空状态也保留窗口占位；失败或取消不清掉上一张成功图。用户查看历史图后，下一个成功成果仍自动切回最新图。预览下可直接将当前图作为参考、复用参数或导出。顶部显示模型和全局运行／等待计数。底部“加入队列”明确批量数量。任务页：队列控制、状态筛选、任务行和错误详情。成果库仍为缩略图网格、时间排序、多选操作，点击打开详情及本地参数；“复用参数”只填草稿，“作为参考图”只追加参考图，都不生成。新生成不清空提示词和参考图，以便连续调整。旧 GNBP UI 仅作布局参考，不复制其图片或素材。

候选尺寸：工作区可用宽度足够时表单约 320px；不足时表单与大图预览纵向排列。1040×760 为主基准，720×520 是当前 Tauri 最小窗口，额外检查 600×740 浏览器布局；文字和控件沿用主题语义变量、8px 圆角、14px 表单正文、13px辅助文字。历史缩略图仅在自身横向滚动区内滚动，窄屏整体纵向滚动，无页面横向溢出。深浅和自定义主题均沿用 Ayase 外观设置，不另起绘图主题系统。

1. 在设置添加绘图连接／模型 → 进入绘图选择该模型。
2. 输入提示词，选协议参数；可导入、拖入或粘贴参考图。显示本地保存状态，校验失败不留下成功假象。
3. 点击加入队列 → 校验配置、文件、预算 → 原子保存批次及单图任务 → 显示任务数。任一步失败不部分派发。
4. 任务按 FIFO 派发；设置快照不随编辑草稿改变；完成后先保存图片，再原子提交成果及任务终态。
5. 预览／导出／复用参数／作为参考图。普通导出不带 Ayase 生成元数据；显式带参数导出说明范围。
6. 需要重新请求时使用明确按钮产生新任务，保留旧任务结果与诊断；结果未知时确认可能重复计费。

参考图显示编号，有顺序，支持查看、移除及调整顺序；同一图片重复添加时提示并跳过。成果“作为参考图”追加到末尾，不覆盖当前提示词、模型及参数，也不自动发送请求；生成后保留参考图。格式参考 GNBP 文件选择的 PNG／JPG／JPEG／WebP／BMP，不增加比 GNBP 更严格的输入要求；不设置额外张数、单图容量、总容量或像素上限，具体模型和中转的输入兼容性由服务商校验，错误明确展示且不静默遗漏图片。这取代原先最多 8 张、单图 20 MiB／32 百万像素、合计 80 MiB 的候选输入预算；现有 #84／#85 输出响应预算不因此改变，也不得直接套到参考图输入。

#86 输入预处理按用户 2026-10-01 确认：只有所选协议的官方文档明确要求时才处理，并在协议边界记录依据及具体规则；否则发送原始私有副本字节，保留尺寸、格式、颜色和透明度，不缩放、不裁切、不有损压缩、不统一转 JPEG 或铺底色。Base64 编码、multipart 封装及正确 MIME 声明属于请求编码，不改变图片内容。2026-10-01 核对的 [Gemini 图文生图示例](https://ai.google.dev/gemini-api/docs/generate-content/image-generation) 直接读取 PNG 并 Base64 编码，[OpenAI Images 编辑示例](https://developers.openai.com/api/reference/resources/images/methods/edit) 直接上传参考文件；未见要求执行 GNBP Gemini 的最长边 1536 像素／JPEG quality 85 处理。官方格式／容量契约不等于必须自动转换／缩小图片，也不授权客户端替供应商增加前置兼容性拦截。本地读取失败、损坏或不可用文件仍明确报错，不静默跳过。

批量／队列候选应用预算仍为单批 1–20 个任务、等待队列最多 100 个任务（提交时计数、整批拒绝越界），由 #87 另行确认；默认数量 1，不在打开页面时提交。

预设默认保存提示词及可选协议参数，不保存 Key，也不隐式绑定参考图或连接。载入预设替换非空草稿前确认；跨协议参数不能直接套用。成果“复用参数”明确确认替换提示词、目标及参数，并恢复该成果仍可用的输入参考图；输入缺失时列出失效项且不生成，不假称完整复现。复用历史参数若目标模型失效，保留提示词与参数并显示未选择状态，要求用户重新选模型；不自动改协议。草稿保存失败保持内存内容并允许重试，退出提示未保存；点击生成须先取得持久快照。

## 4. 连接、模型与协议边界

保留“供应商仅分组、每连接唯一协议、模型唯一父连接”的约束。候选新增两个明确绘图协议：`gemini-image` 与 `openai-images`。同一供应商可拥有聊天和绘图连接；即使地址／Key／实际模型名相同，它们也是不同连接下的已添加模型 ID，不从名称推断生图能力。Gemini 绘图请求使用 GenerateContent；OpenAI 绘图使用 Images，不借用 Chat Completions 或 Responses 的聊天工具路径。

共用设置入口和存储所有者，保留原有四种 `ChatProtocol` 类型；将服务配置的协议分类与聊天 transport 类型分开，以明确的分类／解析函数向各模块提供合法目标。聊天选择器排除绘图模型，绘图选择器排除聊天模型。旧配置、聊天当前模型 ID、助手默认值和对话快照无损保留；设置迁移失败不能清空旧数据。新增配置的备份兼容／旧版恢复保护须随 #84 一并处理；不能等 #93 才发现旧备份不识别绘图协议。

绘图只从共享配置服务取得目标，不调用聊天 hooks／SessionStore，也不修改聊天全局 activeModelId。草稿独立拥有 selectedModelId。新增绘图连接可显式复制用户选中的已有连接字段；不读取 GNBP 配置、不做凭据导入、不自动创建或选择模型。

提交时持久化目标快照：供应商／连接／模型 ID、实际模型名、协议、经校验的不含凭据的地址、参数。API Key 仅在运行时读取与冻结，不进入草稿、任务、成果、PNG 参数或诊断。队列启动前重新解析同一个连接和模型：缺失／地址、协议、模型名变化则阻止派发并要求明确重新配置；只换 Key 可在派发时使用该连接当前 Key，正在运行的请求保留原 Key。删除有待派发／运行任务的连接或模型前必须先取消关联任务，生成期间继续沿用现有配置修改保护，并把绘图任务纳入共享保护计数。

候选 `ImageGenerationTransport.generate(frozenRequest, signal)` 只表达一次生图请求及规范化图片／文本说明／错误；不复用 `ChatEvent` 来表示图库、队列或图片。适配器拥有 URL、认证、映射、响应和错误；队列与存储由独立绘图服务负责。URL 预览与实际请求仍共享确定性 resolver；HTTPS 证书验证保持启用，Key 用头传递，不复制 GNBP 的 query-key／verify=False／禁用代理规则。错误和诊断先脱敏再保存。

官方协议事实仅用于约束适配器，不承诺未知中转兼容：[OpenAI Image API](https://developers.openai.com/api/docs/guides/image-generation) 区分 generations／edits，支持的参数依模型而异；[Gemini 图像生成文档](https://ai.google.dev/gemini-api/docs/generate-content/image-generation) 说明 GenerateContent 图像输入输出。#84／#85 在实施时重新核对官方文档及脱敏契约；首版不固定模型白名单。参数按协议分区；可选字段默认“自动”并省略，不为所有模型强制同一尺寸、质量、temperature 或参考图数量。

每任务请求单张是调度合同（Images `n=1`），不是请求返回值保证。Gemini 等响应若实际返回多张有效图，作为同任务多个成果逐一保存，不静默丢弃额外图片；以本地响应预算限制分配。首版非流式，不提供百分比虚假进度或未确认的中间预览；仅文本、拒绝或无图片显示具体失败，保留可用脱敏说明。OpenAI 首版以图像字节返回为合同，URL-only 中转不自动下载任意地址，显示不支持并要求后续明确扩展。

## 5. 数据归属及图片生命周期

| 对象 | 所有者／持久内容 | 删除与复用 |
| --- | --- | --- |
| 共享连接和已添加模型 | 现有配置服务；地址与凭据仅在连接 | 绘图保存模型引用；不会复制 Key 到任务 |
| DrawingDraft（当前一个草稿） | 绘图仓库；提示词、两协议参数、选中模型、数量、有序参考资源引用、修订号 | 清空只清草稿；不删除已提交任务及成果 |
| DrawingBatch | 绘图仓库；提交次序、数量和同一次请求快照 | 统计由子任务派生，不拥有图片；取消批次逐项取消 |
| DrawingTask | 绘图仓库；批次、不可变请求快照、输入引用、状态、时间、脱敏诊断和可选成果索引 | 仅终态可删除；删除任务历史不删除成果；重试是新 taskId |
| DrawingResult | 成果库仓库；resultId、可选 sourceTaskId、输出图片资源、参数快照、有序输入参考资源引用、时间及尺寸 | 独立持有输入／输出引用；sourceTaskId 是出处而非存活依赖；删除成果不改变任务成功事实 |
| ImageResource | 绘图资源服务；不可变私有字节、MIME、尺寸、摘要及派生缩略图 | DB 所有者引用决定保留；不引用用户原始绝对路径 |
| PromptPreset | 绘图仓库；名称、提示词和可选协议参数 | 删除不改变已加载草稿、任务或成果 |
| 本地结果提交日志 | 原生绘图资源服务与绘图仓库 | 日志未决时独立持有资源，修复完成前不得 GC |
| 导出的图片及参数文件 | 用户选定外部目录 | 与成果库独立；删除库记录不删除外部副本 |

沿用 Ayase 主数据库，通过 DrawingRepository／ResultLibrary 接口访问，React 不访问 Dexie。后续版本增量新增表，不重建或清空聊天表；资源放 app-private `drawing/` 下，原图／参考图与缩略图分目录。Tauri 只负责路径校验、输出图片预算、文件暂存／原子写入／解析／导出，不承载业务页面或模型调度。参考图输入遵循上文 #86 已确认规则，不继承生成成果的容量／尺寸限制；预览派生图不替换发送用的原始私有副本。

导入参考图先验证再复制到私有暂存文件，原子提交草稿引用后发布成功；取消／失败回收本次无主暂存。成功后不依赖源文件继续存在。成果作参考只增加同一不可变资源的拥有者引用，不复制字节、不引用可删除的成果行本身。请求任务保存输入引用，后续移除草稿图不影响排队或运行任务。添加引用与删除／收集持同一生命周期锁，引用提交失败不得抢先删除文件。

#86 已确认的清理语义：添加／提交失败时只清理本次没有任何拥有者的临时资源；已登记任务失败或取消仍保留输入引用，便于追查及后续复用。移除草稿参考图只释放草稿拥有的引用，不能删除任务或成果仍引用的图片。这解释远端 #86 的“失败和取消后的资源可正确清理”，不表示扩展 #86 为完整任务／成果删除界面。

删除成果须确认。一次事务删除库记录及任务上的展示索引，但任务保留成功状态和参数；输入草稿／其他任务中的同一资源引用仍有效。取消／失败任务也保留输入以便明确重试，直到用户删除任务历史。删除历史只移除任务拥有的输入引用，不删独立成果；成果自行持有的输入引用继续用于复用，删除成果才释放这些引用。没有年龄或容量驱动的自动删除用户记录。预览临时租约、导出、未决提交日志及恢复日志均是 GC 保留集合的一部分；损坏／不可读取的元数据使清理暂停，不以空列表推断全部无主。派生缩略图可重建，不能拿原图为全部网格兜底。

资源回收候选采用现有附件经验：最后引用释放后隔离，至少 30 天、两次间隔至少一小时的完整无主扫描后才物理删除；重新引用可恢复。新暂存且从未提交的无主文件可在安全恢复后清理。绘图独立管理目录，与聊天附件／头像／背景清理器互不扫描。将来 #91 另行定义跨模块副本／引用策略，首版不引入跨库图片依赖。

## 6. 批量、并发与取消

先校验并落盘整个批次再派发；重复点击提交用同一提交令牌合并，不以重复任务换取 UI 响应。不同明确提交创建不同批次。FIFO 以持久提交顺序决定，默认并发 1、最大 4，指整个绘图模块的运行槽，不乘以连接数量；槽覆盖准备、网络及保存，防止网络完成后四份大图又同时追加解码。

提高并发立即补充派发；降低并发不取消现有运行任务，待占用数低于新值再启动后续任务。“暂停队列”只阻止新任务启动；运行中任务继续。单项／批次取消独立于其他任务。排队项直接取消且零网络；请求可能已经发出时 Abort 只停止本地等待，界面标明远端可能继续／计费，不承诺撤销供应商任务。

候选内部状态：`queued → preparing → dispatching → running → saving → succeeded`；任何阶段的本地确定失败进入 failed／save-failed，未发送取消进入 cancelled，可能发送但无确定结果进入 outcome-unknown。dispatching 必须在实际网络发送前持久化“可能发送”标记，崩溃后宁可结果未知，不冒险重复发。终态只能以明确新任务再请求；保存失败仅重试本地保存，不触发生成。

取消与成功竞态按服务串行提交：有效响应尚未耐久暂存，取消先被接受则终态取消／未知；有效结果已耐久暂存，后来的取消不能删除已收到图像，转为“正在保存”并补完本地提交。取消回调与网络迟到回调不能重复产生结果。resultId 由 taskId + 响应序号确定，成功提交幂等；数据库只允许一次有效终态发布。

保留旧任务，用户“重新生成”产生新任务并显示费用提示；并发点击同一个失败／未知任务的重新请求须用命令令牌防重，已有进行中的直接替代任务返回同一 ID。服务器明确 429／500／无图、网络错误、超时及取消都不自动 retry／fallback。

## 7. 关闭、重启与结果恢复

切换聊天／绘图／设置不关闭绘图服务。调度器是应用级单一所有者，组件卸载不销毁任务；与聊天调度器互不占用同一运行槽。关闭窗口不引入托盘常驻；有未完成任务或未保存草稿时提示，选择继续使用则不退出。确认退出后先停止派发、保存草稿和队列、终止本地网络；已暂存结果先完成安全保存或留下耐久恢复日志，再退出。退出有有界等待；失败需可见，不能无限冻结或报告远端已取消。

重启恢复顺序：既有 Ayase 备份恢复门禁 → 绘图文件／结果提交日志修复 → 读取草稿、任务与成果 → 展示页面并保持队列暂停。用户点击继续队列只恢复确定未发送的 queued 项，重新预检目标与文件；结果未知项不加入待执行队列。

| 崩溃点／已保存状态 | 本地恢复动作 | 网络行为 |
| --- | --- | --- |
| 草稿已保存；queued／preparing 且没有派发标记 | 恢复草稿；任务回到 queued 并暂停 | 等用户继续队列 |
| dispatching／running，无耐久图片结果 | outcome-unknown，解释可能已经计费 | 不重发；只能用户确认新建任务 |
| 图片已耐久暂存、尚未注册成果 | 核验日志，幂等补存原图及成果／任务终态 | 只修复本地文件与 DB |
| 原图已落盘、DB 未提交 | 使用确定资源 ID／摘要重新核验并提交 | 不再次保存不同文件或请求模型 |
| DB 已提交、日志未清理 | 核验现有结果后清理日志，避免重复成果 | 不联网 |
| 保存介质不可写／日志损坏 | 显示保存待修复或失败，保留可恢复文件；禁止相关 GC／派发 | 显式重试本地修复，不生成 |
| 已成功或其他确定终态 | 原样恢复；图片缺失时标记不可用，不伪造成功预览 | 不联网 |

备份恢复的 queued 项也默认暂停；运行项没有可恢复本地结果则归入结果未知。初期 #84 必须已有单张结果的落盘／提交保护，#88 扩展完整队列与重启状态，不能把可靠保存全部推迟。

## 8. 保存、导出与隐私

成果原始图像字节保存到应用私有目录；提示词与协议参数以结构化元数据存入 DB，不默认写入 PNG。普通导出重新输出可验证的图片容器，移除 Ayase／GNBP 生成参数以及可能暴露用户文件路径的 EXIF／文本元数据；不只做原始字节复制。保留图像色彩／透明度和服务商内置的像素或必要来源标记，不承诺去除 SynthID 等水印。原始私有副本不修改。

候选“带参数导出”先采用同名图片 + Ayase JSON 侧文件，包含提示词、实际模型名、协议、有效参数、生成时间、参考图数量及尺寸；不含 Key、Base URL、连接名称／ID、机器路径、参考图文件名、输入图片字节、原始 HTTP 响应或诊断。导出前显示元数据提示。它不等同于 #92 的 GNBP PNG 兼容；#92 将来需显式选用，不改变普通导出默认值。

隐私提示要区分：普通导出不附带隐藏生成参数，但图像像素仍可能包含提示词或参考图里的敏感内容；本地 DB 本身存有提示词与连接配置，延续 Ayase 明文本地存储边界。不得把 Key／源绝对路径写入日志、错误、任务或图片；不自动上传图库，不在列表渲染时从网络获取图像。

成果保存失败不能显示生成成功；展示“已收到图片，保存失败”并保留耐久暂存后的本地重试入口。若连暂存都失败，清楚说明结果尚未可靠保存，不宣称重启可恢复。多图响应一个任务全部资源及元数据完成后发布成功；部分本地保存进度由日志保留，修复只补缺项。

## 9. 备份及分阶段保护

#84 首次新增共享绘图配置／持久草稿／图片时，就扩充完整备份快照和校验，或显式阻止旧导出／替换流程并说明未支持数据；不能静默导出一个看似完整却遗漏绘图的备份。优先在每个切片同步扩展格式，#93 完成全范围及跨模块故障回归。旧版备份仍可读，缺绘图区不代表删除当前绘图；替换须明确预览影响范围。

进入维护前共同禁止新聊天／绘图提交，检查绘图队列、草稿保存、预览／导出及文件写入租约；暂停调度并刷新仓库。运行请求必须等待或由用户明确中止，不能靠切页卸载取消；不能将仍在保存的数据纳入快照。维护门禁覆盖共享配置、绘图仓库和私有文件。旧恢复日志先修复，再恢复绘图日志，之后才启动任何 GC。

备份包含绘图草稿、预设、任务／批次、成果、所有被保留输入及输出资源、共享连接；排除缩略图、运行时 Key 快照、HTTP 句柄和预览缓存。现有完整备份连接／密钥规则及默认关闭的加密开关保留。恢复重映射 taskId／resultId／resourceId／modelId 并校验拥有者；重启或恢复都不自动产生请求。

## 10. 性能验收候选指标

当前开发机只读确认：Windows 10 Pro 19045、i9-14900KF、约 64 GiB RAM；窗口配置 1040×760／最小 720×520。这些不是性能测量结果。#94 记录 WebView2 版本、屏幕缩放、构建模式及图片集；推荐另加 4 核／16 GiB Windows 10/11、SSD、WebView2 的常规机验收，当前机器通过不代表常规机已测。

| 场景 | 候选目标与测量方法 |
| --- | --- |
| 1,000 张持久成果（含 4096×4096 原图）、50 个终态任务分页 | 首屏元数据／缩略图 ≤ 1s；只解码视口附近缩略图，图片量不引起全库原图读入 |
| 20 单图批次、并发 1→4→1，8 张参考图（性能样例，不是输入张数上限） | 顺序／槽数正确，无 50ms 以上持续主线程解码／Base64工作；本地提交确认 p95 ≤ 500ms |
| 四路 4K 合成图片响应，单响应总字节候选上限 64 MiB、单图 32 百万像素 | 绘图额外进程工作集峰值 ≤ 1.5 GiB；解码／存储占槽，有界处理，超过预算明确拒绝 |
| 停止、切聊天、滚图库、开启预览、保存同时进行 | 取消 UI p95 ≤ 100ms、页面切换 p95 ≤ 200ms；不把远端耗时当本地性能 |
| 批次结束／预览关闭后 30s，与热身后的空闲基线比较 | 额外工作集 ≤ 200 MiB；重复 5 轮不持续线性增长；原图／Base64／Object URL 租约释放 |
| 运行中断网／窗口退出／进程终止／写盘或 DB 失败 | 恢复不重复网络、不丢已耐久保存成果、不收集仍有主文件；模拟精确计数 |

这些数值是 #83 提出的验收目标，待整体验收后作为 #94 门禁；尚未测量，也不含供应商出图速度、计费或图片质量承诺。图库虚拟化／懒加载、512px 缩略图、按需原图、后台解码和释放临时字节为实施方向。不能只凭 API 等待占大部分时间就认定应用轻量。
