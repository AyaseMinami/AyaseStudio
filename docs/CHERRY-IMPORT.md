# 导入 Cherry Studio 聊天备份

在 Ayase Studio 的「设置 → 数据导入」点击「导入 Cherry Studio 聊天」，选择本机备份 ZIP。读取和导入均在本地完成，不上传备份，也不发送模型请求。

## 支持范围与验证边界

| 备份格式 | 来源与识别条件 | 聊天来源 | 已验证范围 |
| --- | --- | --- | --- |
| 5 | 已提供的 Cherry Studio 1.9.13「导出至手机 → 导出到文件」结构；包含聊天表的 `data.json` | 有序话题消息与消息块 JSON | 本地真实结构检查及合成用例；不能仅凭数字 5 推断其他版本兼容 |
| 6 | `metadata.json` 的应用版本必须为 1.9.13 | Chromium 的 Local Storage / IndexedDB | 合成解析用例，以及真实备份的隔离预览与手机 JSON 全部聊天记录语义对照；未导入当前用户数据 |
| 7 | `metadata.json` 的应用版本必须为 2.1.3，SQLite 必须匹配固定源码的 26 项迁移识别记录 | `Data/cherrystudio.sqlite` | 固定源码、合成 SQLite 与合成 ZIP 用例；真实 2.1.3 导出仍待验收 |

格式 6 即使含有遗留 SQLite 文件，也沿用 Chromium 聊天来源。格式 7 完整和精简备份均可识别；精简备份可能只剩附件元数据。不会根据扩展名、SQLite 文件是否存在或相近应用版本猜测格式，不承诺任意 1.9.x 或 2.x 备份兼容。

格式依据见 [1.9.13 的普通备份元数据](https://github.com/CherryHQ/cherry-studio/blob/da22fb797343fd3760e5dd2d467eda9bf0017632/src/main/services/BackupManager.ts#L141-L158)、[1.9.13 的手机导出载荷](https://github.com/CherryHQ/cherry-studio/blob/da22fb797343fd3760e5dd2d467eda9bf0017632/src/renderer/src/services/BackupService.ts#L886-L893)及 [2.1.3 的备份元数据](https://github.com/CherryHQ/cherry-studio/blob/3b397393b129558dcfadfaf4141e2a2395ac5eeb/src/main/services/LegacyBackupManager.ts#L209-L232)。SQLite 识别固定到 [2.1.3 提交](https://github.com/CherryHQ/cherry-studio/commit/3b397393b129558dcfadfaf4141e2a2395ac5eeb)，迁移指纹保存在 [只读解析器](../src-tauri/src/cherry_sqlite.rs)，不会执行备份中的迁移 SQL。前期调查与版本对照见 [外部研究记录](ISSUE-77-EXTERNAL-RESEARCH.md)；实施状态以 [实施记录](ISSUE-77-IMPLEMENTATION.md) 为准。

## 选择和确认

1. 查看预览中的助手分组、对话标题、消息和附件数量。可按助手或单个对话选择，也可全选、取消全选；空对话可以导入。
2. 检查分支展开和缺失附件提示。所选范围的附件计数按消息中的附件条目统计；同一来源出现在多个独立分支时，各分支分别计数。
3. 选择「默认跳过已导入」或「另存副本」，点击「导入所选对话」。确认后直接执行，不再增加第二次确认弹窗。
4. 查看导入、跳过数量及提示。导入失败时保留预览和选择，可重试；成功后清除本次预览，再次导入需重新选择文件。

导入时保留助手分组、标题、角色、原有顺序、可恢复时间、正文和思考内容。旧格式中具有同一 `askId` 的平行回答展开为独立有序路径；没有明确关联的连续回答保留原有顺序。SQLite 树保留所有根到叶路径，活动路径优先显示。虚拟根节点不进入聊天正文，对话标题以「分支 N」区分路径。

重复识别使用来源话题和该路径中有序的来源消息 ID；SQLite 虚拟根 ID 也参与来源路径。正文变更不会让相同来源路径自动变成新对象。「默认跳过」保留已存在的导入；「另存副本」生成新的本地 ID 并保留已有副本，不覆盖现有对话。

## 附件和未支持内容

仅恢复备份内部 `Data/Files/` 中可验证、属于既有支持类型的附件，保存为 Ayase 受管私有副本。支持类型沿用现有附件模块：PNG/JPEG/WebP、PDF、UTF-8 常用文本/代码、DOCX/XLSX/PPTX。导入器不下载 URL，不读取外部路径，也不读取备份内容中的 data URL。图片和文件通过现有附件展示与预览边界读取。

缺失、不支持或外部附件只要仍有安全的文件名元数据，就保留文件名描述，并在导入后的消息中显示；元数据也已缺失的附件只能给出统一提示。外部文件即使在 ZIP 中存在同名条目也不读取。原消息正文继续保留。预览和结果给出统一提示，不把原始错误、配置或路径写入提示。工具、搜索、引用等未支持块以统一提示报告，不恢复工具执行、运行时或请求回放。

不导入 API Key、账户、供应商、模型连接、助手提示词或生成配置。导入后的助手与对话没有 Cherry 模型绑定，不触发自动命名或网络请求。继续聊天前，请显式选择 Ayase 中已有的模型；后续发送遵循该模型连接的正常行为。

## 事务与限制

旧格式的空对话若只在一个助手的对话列表中出现，但其 `assistantId` 仍指向旧助手，会按列表中的唯一归属恢复并显示提示，即使旧助手仍然存在。对话同时出现在多个助手列表、非空对话的有效助手归属冲突或消息归属冲突仍会拒绝导入，不会猜测或静默丢弃对话。

助手、对话、消息和重复导入标记在单个数据库事务中提交。所选附件先暂存并核验，数据库提交前失败会丢弃暂存副本，聊天记录整批回滚。数据库提交成功后，附件或备份资源整理失败只报告警告，不误报聊天回滚，也不丢弃已提交附件。

为防止损坏备份和分支展开耗尽资源，超限或结构矛盾会拒绝导入，不静默截断：

| 范围 | 上限 |
| --- | --- |
| ZIP 压缩文件大小、声明展开总量 | 各 2 GiB |
| ZIP 条目 | 50,000 |
| 聊天源文件提取 | 128 MiB |
| 单个附件 | 64 MiB |
| 单次备份会话附件累计读取 | 1 GiB |
| 展开的对话/路径 | 2,000 |
| 输入及展开消息 | 100,000 |
| 输入及展开内容块 | 200,000 |
| 单个文本字段 | 8 MiB |
| 聊天文本合计 | 64 MiB，同时限制源内容与展开后的内容 |

当前可确认的范围不包含真实 2.1.3 导出验收，也不包含把真实备份写入当前用户数据。浏览器、原生启动和最终代码门禁状态请查看实施记录，不将合成用例等同于真实迁移完成。
